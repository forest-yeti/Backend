# Клиент. Задача 11. «Не ждать большого блайнда»

Документ для разработчика Electron-клиента. Дополняет
[задачу 2](2_CashGame.md), §«Вход в игру: `entry`».

Кнопка, которую клиент уже рисует по флагу `can_post`, **до сих пор ничего
не делала**: сервер сообщал о возможности войти за взнос, но сообщения,
которое её реализует, не существовало. Теперь оно есть — и его нужно
подключить.

Механика общая для всех форматов: кэш, турнир, sit-n-go. Ждать блайнда и
платить за вход вне очереди — правило про порядок круга, а не про формат.

---

## 1. Зачем вообще ждать

Игрок, севший за стол, обычно ждёт своего большого блайнда и только потом
вступает в игру. Иначе вход был бы способом не платить блайнды: сел за
кнопкой, сыграл лучшие позиции круга бесплатно, встал перед блайндами —
и так по кругу, за чужой счёт.

Кто ждать не хочет, платит за вход столько же, сколько круг стоит уже
сидящему. Это и есть **взнос** (post).

---

## 2. Сообщение

```
"post_blind" %{}                 → :ok    # хочу войти за взнос
"post_blind" %{post: false}      → :ok    # передумал, жду блайнда
```

Ответы об ошибке:

| Код | Когда |
|---|---|
| `post_not_available` | игрок и так играет, либо вход за взнос сейчас недоступен (`can_post: false`) |
| `not_seated` | не сидит за столом |
| `leave_in_progress` | уже встаёт из-за стола |

---

## 3. Главное: это намерение, а не мгновенный вход

Нажатие **не вводит игрока в игру немедленно**. Сервер запоминает намерение
и превращает его в решение в момент старта ближайшей раздачи.

Причина не техническая, а игровая: во что обойдётся вход, зависит от того,
где будет кнопка, а между нажатием и стартом раздачи она сдвигается. Взнос,
посчитанный на момент нажатия, был бы посчитан не для той раздачи.

Отсюда поведение интерфейса:

* нажали — кнопка переходит в состояние «включено» (`you.wants_post: true`),
  но игрок остаётся `waiting_for_bb` до начала следующей раздачи;
* с началом раздачи `waiting_for_bb` и `wants_post` гаснут сами, игрок
  появляется в раздаче, а взнос уже списан со стека;
* если игрок передумал до старта — `%{post: false}`, и всё как было.

Не показывайте «вы в игре» по ответу `:ok`. Источник истины — снапшот и
события стола.

---

## 4. Что приходит с сервера

**В снапшоте**, в блоке `you`:

```json
{
  "waiting_for_bb": true,
  "can_post": true,
  "wants_post": true,
  "post_required": false
}
```

* `can_post` — **можно ли** нажать. Нет — кнопку не показывать вовсе.
* `wants_post` — **нажато ли** уже. По нему рисуется состояние кнопки, в том
  числе после реконнекта.
* `post_required` — особый случай: игрок встал и сел обратно внутри окна
  возврата, и права «просто ждать» у него больше нет. Здесь вход за взнос
  не выбор, а условие возвращения в игру — это стоит сказать словами.

В `seats[]` публично приходит `wants_post` соседей: за живым столом видно,
что человек собирается войти, и скрывать это незачем.

**Событие** — всем за столом:

```
"seat_posting"  { "seat": 4, "wants_post": true }
```

**Взнос в раздаче** приходит теми же событиями `posted`, что и блайнды,
с новыми значениями `kind`:

```
{ "seat": 4, "kind": "post",      "amount": 10, "pot": 25 }
{ "seat": 4, "kind": "dead_post", "amount": 10, "pot": 35 }
```

---

## 5. Живой и мёртвый взнос — разные вещи

Это единственная деталь, которую нужно показать игроку правильно, иначе он
решит, что у него украли фишки.

| Вид | Что это | Как показывать |
|---|---|---|
| `post` (живой) | ставка наравне с большим блайндом | фишки перед игроком, как блайнд |
| `dead_post` (мёртвый) | уходит **сразу в банк**, ставкой не считается | фишки в центре стола, не перед игроком |

Живой взнос даёт то же, что и блайнд: если никто не поднял, отвечать
игроку нечем — ставка уже сделана. Мёртвый в его ставку не идёт: игрок всё
равно должен будет ответить на большой блайнд, когда до него дойдёт ход.
Мёртвым взнос становится, когда игрок входит между кнопкой и большим
блайндом, то есть круг блайндов в этой раздаче он проходит мимо.

Оба могут прийти одновременно (часть живая, часть мёртвая) — рисуйте их
раздельно, по `kind`.

Считать суммы не нужно: они приходят готовыми, а стек и банк обновляются
обычными событиями раздачи.

---

## 6. Что править

1. Повесить на существующую кнопку отправку `post_blind` — сейчас она,
   судя по всему, не отправляет ничего.
2. Состояние кнопки брать из `you.wants_post`, а не из локальной переменной:
   иначе после реконнекта оно потеряется.
3. Добавить `post_not_available` в обработку кодов.
4. Развести в интерфейсе `post` и `dead_post` (§5).
5. Не считать `:ok` подтверждением входа в игру (§3).

---

## 7. Чек-лист приёмки

* [ ] Кнопка показывается только при `can_post: true`.
* [ ] Нажатие отправляет `post_blind`, повторное — снимает намерение.
* [ ] После нажатия игрок остаётся в ожидании до начала следующей раздачи.
* [ ] С началом раздачи игрок появляется в ней, а взнос виден списанным.
* [ ] Реконнект сохраняет состояние кнопки (`wants_post` из снапшота).
* [ ] Мёртвый взнос нарисован в банке, а не перед игроком.
* [ ] `post_required` объяснён игроку как условие возврата, а не как выбор.
* [ ] Намерение соседа видно за столом (`seat_posting` / `seats[].wants_post`).
