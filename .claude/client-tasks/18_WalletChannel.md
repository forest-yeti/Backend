# Клиент. Задача 18. Канал кошелька

Документ для разработчика Electron-клиента. **Содержит исправление
существующего бага, а не только новую фичу** — читать обязательно, даже
если баланс у вас «и так работает».

---

## 1. Что было сломано

Баланс уходил клиенту **ровно один раз** — в ответе на `POST /api/auth/login`
(поле `wallets`). Больше он не приходил никогда.

Дальше игрок садился за стол, закупался, вставал, закупался снова — и всё
это меняло баланс в базе, но не на экране. Через несколько сессий на экране
оставалась цифра многочасовой давности.

Реальный случай: игрок видел `1570`, жал «закупить 400» и получал
«Недостаточно средств». В базе у него к тому моменту было `370` — четыре
бай-ина после логина клиент просто не увидел. Ошибка сервера была верной,
врал экран.

**Вывод для клиента: баланс, полученный при логине, — стартовое значение,
а не источник истины.** Держать его как «текущий» нельзя.

---

## 2. Топик

```
wallet:<user_id>
```

`user_id` — свой собственный, из ответа логина. Подписаться на чужой
кошелёк нельзя: сервер сверяет топик с личностью соединения и отвечает
`not_found`. Не пытайтесь использовать это как «посмотреть баланс соперника» —
такой возможности нет и не будет.

Подключаться сразу после `connect`, вместе с `lobby`, — до первого входа
за стол, а не в момент закупки.

---

## 3. Снапшот при join

Ответ на join:

```
%{wallets: [
  %{type: "main",       amount: 0},
  %{type: "play_money", amount: 370}
]}
```

`amount` — целое в минимальных единицах (§5 протокола), без дробей.
Список содержит **оба** кошелька; ищите нужный по `type`, а не по индексу.

Этим снапшотом нужно **заменить** значение из ответа логина, а не
дополнить его.

---

## 4. Событие движения денег

```
"wallet_entry" %{
  wallet: "play_money",
  amount: 370,
  entry: %{
    seq: 161,
    type: "buy_in",
    amount: -400,
    ref_id: null,
    at: "2026-08-19T15:33:44.442000Z"
  }
}
```

Разделение полей важное:

* `amount` **верхнего уровня** — новый баланс кошелька. Это то, что рисуется.
  Его не надо ниоткуда вычитать и никуда прибавлять — просто присвоить.
* `entry.amount` — сама операция, **знаковая**: бай-ин отрицателен, кэш-аут
  положителен. Знак выводить из `entry.type` не нужно и нельзя.
* `entry.seq` — счётчик базы, строго возрастающий. По нему упорядочивается
  выписка; по времени `at` сортировать нельзя (операции попадают в одну
  микросекунду).

Типы операций: `deposit`, `buy_in`, `cash_out`, `rake`, `adjustment`.
Неизвестный тип не должен ломать экран — баланс всё равно берётся из
`amount` верхнего уровня.

**Считать баланс самим — запрещено.** Не прибавляйте `entry.amount` к
своей цифре: расхождение накопится ровно так же, как накопилось до этой
задачи. Источник истины — `amount`, присланный сервером.

---

## 5. Перезапрос

```
"balance" %{}  →  reply: %{wallets: [...]}
```

Когда звать:

* **обязательно** — получив `insufficient_funds` на бай-ин или докупку;
* после реконнекта, если не переподключали канал заново;
* при открытии экрана кассы.

Первый пункт — прямая страховка от того бага, с которого начался документ.
Отказ по деньгам всегда означает, что ваша цифра могла устареть: покажите
пользователю ошибку **и одновременно** обновите баланс, чтобы он увидел
настоящую сумму, а не спорил с экраном.

---

## 6. Чего в событии нет

* Событие приходит **только по своим** операциям. Чужих не будет.
* Проигрыш или выигрыш фишек **за столом баланс не меняет** и события не
  порождает. Пока игрок сидит, его деньги — это стек, а не кошелёк;
  в кошелёк они возвращаются одним `cash_out` при вставании. Не ждите
  `wallet_entry` после каждой раздачи и не рисуйте по нему результат игры.
* Неудачная операция события не порождает: отказ по деньгам — это ответ
  на ваш запрос, а не push.

---

## 7. Чек-лист приёмки

* [ ] Канал `wallet:<user_id>` подключается сразу после `connect`.
* [ ] Баланс из ответа логина заменяется снапшотом join, а не живёт дальше.
* [ ] Баланс на экране обновляется по `wallet_entry` присвоением
      `amount`, а не сложением.
* [ ] Кошелёк ищется по `type`, а не по позиции в списке.
* [ ] `insufficient_funds` вызывает `balance` и обновление экрана.
* [ ] Знак операции берётся из `entry.amount`, а не выводится из типа.
* [ ] Закупка → возврат за стол → проверка: цифра в кассе совпадает
      с суммой, которую показывает сервер, без перезахода в приложение.
