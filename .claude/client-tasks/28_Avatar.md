# Клиент. Задача 28. Аватар игрока

Документ для разработчика Electron-клиента.

Аватар перестал быть путём к картинке. Раньше сервер присылал
`"/users/avatars/default.png"` — строку, которую клиент подставлял в `src`.
Теперь сервер присылает **метку набора**: короткую строку, по которой клиент
сам решает, какую картинку из своих ресурсов нарисовать.

Причина та же, что у косметики (задача 20): сервер не должен знать ничего
про изображения, размеры и раскладку. Он хранит выбор игрока строкой, а
рисование — целиком ваша сторона.

---

## 1. Значения

| `avatar` | |
|---|---|
| `"First"` | значение по умолчанию, стоит у всех новых учёток |
| `"Second"` | |
| `"Third"` | |
| `"Four"` | |
| `"Five"` | |

Регистр значим: сервер присылает и принимает ровно `First`, а не `first`.

Список будет пополняться. **Неизвестную метку рисуйте как `First`** —
не падайте, не показывайте пустой квадрат и не логируйте это как ошибку.
Новый аватар заводится на сервере одной строкой, а Electron обновляется
не у всех и не сразу; старый клиент обязан пережить незнакомое значение.

```js
const AVATARS = {
  First: "assets/avatars/first.png",
  Second: "assets/avatars/second.png",
  Third: "assets/avatars/third.png",
  Four: "assets/avatars/four.png",
  Five: "assets/avatars/five.png",
};

function avatarSrc(avatar) {
  return AVATARS[avatar] ?? AVATARS.First;
}
```

`seat.avatar` может прийти `null` (место занято, но профиль не подтянулся) —
это тот же случай `First`.

---

## 2. Где приходит

Ничего нового подписывать не нужно, поле уже есть в двух местах:

* **Профиль владельца соединения** — ответ `POST /api/auth/register`,
  `POST /api/auth/login`, `POST /api/auth/refresh`:

  ```json
  { "user": { "id": "...", "name": "Player", "email": "...", "avatar": "First" } }
  ```

* **Место за столом** — в `table_state` и `table_delta`, рядом с `name`
  и `flair`:

  ```json
  { "seat": 3, "name": "Player", "avatar": "Second", "flair": "default", ... }
  ```

---

## 3. Смена аватара

Топик — `lobby` (аватар не относится к конкретному столу, и менять его
можно, не сидя ни за одним).

Клиент → сервер:

```
"set_avatar"  %{avatar: "Third"}
```

Ответ — reply на то же сообщение:

```json
{ "avatar": "Third" }
```

В ответе всегда **фактическое** значение, сохранённое сервером. Рисуйте
именно его, а не то, что отправили: если ответ разошёлся с ожиданием —
прав сервер.

Ошибки — обычным форматом `%{code: ..., message: ...}`:

| `code` | Когда |
|---|---|
| `validation_failed` | метки нет в списке известных, поле пустое или не строка |
| `not_found` | учётка исчезла (в норме не встречается) |

Оптимистично перерисовывать аватар до ответа не надо: смена — редкая
операция без гонки за время, и лишний откат UI при `validation_failed`
дороже, чем 50 мс ожидания.

---

## 4. Когда новый аватар видят соседи

Стол снимает профиль игрока **один раз, в момент посадки** — стол
показывает игрока ником и картинкой, а не UUID, и не ходит в базу на каждый
снапшот. Из этого следует поведение, которое надо честно показать в UI:

> Смена аватара во время сидения за столом не меняет картинку на этом столе
> ни у вас, ни у соседей. Новый аватар применится со следующей посадки.

Практический вывод: экран смены аватара уместнее в лобби, а не в оверлее
поверх стола. Если вы всё же даёте менять его за столом — покажите
подпись вида «применится за следующим столом», иначе игрок решит, что
кнопка не сработала.

## 5. Чек-лист

- [ ] `avatar` больше нигде не подставляется в `src`/`<img>` как путь.
- [ ] Есть таблица «метка → ресурс» и фолбэк на `First`.
- [ ] `null` и незнакомая строка рисуются как `First`, без ошибок в консоли.
- [ ] Экран выбора аватара шлёт `set_avatar` в топик `lobby`.
- [ ] UI перерисовывается по значению из reply, а не по отправленному.
- [ ] `validation_failed` показывается человеку, а не молча глотается.
- [ ] Если смена доступна за столом — есть подпись про следующую посадку.
