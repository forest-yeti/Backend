# Клиент. Задача 15. Реакции за столом

Документ для разработчика Electron-клиента. Дополняет
[задачу 8](8_Chat.md): реакции — соседний механизм, но не чат.

Игрок жмёт смайлик, тот всплывает **над его аватаром** и гаснет. Видят все,
кто сейчас за столом. Вся анимация — на клиенте; от сервера приходит только
факт «место 3 отреагировало вот этим».

---

## 1. Передаётся id, а не символ

```
"reaction" %{id: "fire"}
```

Никакого юникода ни в протоколе, ни в базе. Причина не в экономии: версии
эмодзи расходятся между платформами, ZWJ-последовательности и вариационные
селекторы ломаются при нормализации, а произвольный символ, пропущенный
сервером, — это способ написать за столом что угодно в обход фильтра чата.

id — строчная латиница и `_`, он **вечный** и не переименовывается. Картинку
за id выбирает клиент и может сменить её без участия сервера.

Стартовый набор:

| id | символ |
|---|---|
| `fire` | 🔥 |
| `laugh` | 😂 |
| `cry` | 😭 |
| `gg` | 🤝 |
| `clown` | 🤡 |
| `think` | 🤔 |
| `salt` | 🧂 |

**Захардкоживать этот список нельзя.** В снапшоте стола приходит поле:

```
reactions: ["fire", "laugh", "cry", "gg", "clown", "think", "salt"]
```

Панель рисуется **ровно этим списком и в этом порядке**. Порядок — часть
протокола: он задаёт раскладку панели, и менять его на клиенте не нужно.

Обратное правило столь же важно: **неизвестный id не рисуется вовсе**.
Если в броадкасте пришёл id, которого нет в вашей таблице картинок, событие
молча игнорируется — старая сборка не должна показывать пустой квадрат.

---

## 2. Броадкаст

Всем в топике `table:<id>`, включая самого отправителя:

```
"reaction" %{seat: 3, user_id: "...", id: "fire", at: "2026-08-19T09:12:33.412Z"}
```

`seat` — место отправителя, над ним и всплывает. Поля «кому» нет: реакция
всегда «от себя», адресных реакций сопернику в протоколе не существует.
`at` — время сервера, для порядка событий; отсчитывать по нему анимацию
не нужно, рисуйте от момента получения.

---

## 3. Кулдаун: раз в минуту

Реакция дороже сообщения в чате: она всплывает поверх стола сразу у всех.
Поэтому лимит жёсткий — **одна реакция в минуту на игрока**.

Отказ приходит с остатком времени:

```
%{code: "reaction_rate_limited", message: "...", retry_after_ms: 42000}
```

Показывайте **таймер вместо ошибки**: панель гасится на `retry_after_ms`,
кнопки становятся неактивными, по истечении оживают сами. Кнопка, которая
молча не работает, провоцирует повторные нажатия — и отказов становится
больше, а не меньше.

Кулдаун личный: сосед по столу не ограничен вашим. Отклонённая попытка
кулдаун **не продлевает** — отсчёт всегда идёт от последней удавшейся
реакции.

Клиенту стоит вести и свой таймер, но источник истины — сервер: после
реконнекта локальный отсчёт можно потерять, отказ придёт всё равно.

---

## 4. Кто может слать

Любой, кто **занял место**: играющий, сидящий в sit-out, вернувшийся после
обрыва. Наблюдателю — `not_seated`: реакция всплывает над аватаром, а у
наблюдателя аватара за столом нет.

Чтобы не ловить отказ на нажатие, в снапшоте есть флаг:

```
you: %{ ..., can_react: false }
```

`false` → панель не показывать вовсе. Поле приходит и наблюдателю
(`you: %{seated: false, can_react: false}`), так что ветвиться нужно по
одному признаку, а не по «сижу ли я» плюс «есть ли ключ».

---

## 5. Эфемерность

Реакция **нигде не хранится**. Её нет в `chat` снапшота, нет в истории
раздачи, и при реконнекте она не переигрывается: подключившийся не получает
пачку чужих смайликов залпом. Пропустил — значит пропустил.

Отсюда следствие для интерфейса: не стройте на реакциях ничего, что должно
пережить перезаход. Ни счётчиков, ни лент, ни «последних реакций стола».

---

## 6. Ошибки

| Код | Когда |
|---|---|
| `validation_failed` | id не из списка `reactions` |
| `not_seated` | наблюдатель либо игрок уже встал |
| `reaction_rate_limited` | кулдаун; в payload — `retry_after_ms` |
| `leave_in_progress` | игрок встаёт из-за стола |

---

## 7. Чек-лист приёмки

* [ ] Панель строится из `reactions` снапшота, порядок — оттуда же.
* [ ] Список id нигде не захардкожен.
* [ ] Неизвестный id в броадкасте игнорируется, пустой квадрат не рисуется.
* [ ] Своя реакция рисуется по броадкасту, а не оптимистично по нажатию:
      отказ не должен оставлять на экране смайлик, которого не видел никто.
* [ ] `reaction_rate_limited` показывается таймером, а не сообщением
      об ошибке; панель оживает сама.
* [ ] Панель скрыта при `you.can_react: false`.
* [ ] После реконнекта чужие реакции не всплывают пачкой.
