# Клиент. Задача 30. Турнирный покер: MTT, расписание, билеты

Документ для разработчика Electron-клиента. Новый режим рядом с кэшем и
Sit & Go. Дополняет [задачу 2](2_CashGame.md), [задачу 3](3_Hand.md),
[задачу 23](23_MoneyUnits.md) и [задачу 26](26_SitAndGo.md).

MTT — многостоловый турнир, который начинается **по часам**, а не по
набору. Игроков пересаживают между столами, столы схлопываются, выжившие
собираются на финалку. Приз — не лотерея, а сетка выплат по местам.

**Sit & Go остаётся отдельным режимом и отдельным экраном.** Общего у них
только стол: игра идёт в том же топике `table:<room_id>`, и всё, что вы
написали для кэша, работает без изменений.

---

## 1. Чем MTT отличается от Sit & Go

| | Sit & Go | MTT |
|---|---|---|
| Старт | как собрался состав | по расписанию, в назначенное время |
| Столов | один | сколько нужно под явку |
| Вход | однократный | + поздняя регистрация, ре-энтри, аддон |
| Оплата входа | деньги | деньги **или билет** |
| Приз | множитель к взносу (лотерея) | сетка выплат по местам, гарантия |
| Пересадки | нет | есть, между раздачами |
| Перерывы | нет | каждый час в `XX:55`, пять минут |
| Голова за игрока | нет | есть в баунти-турнирах |

Что **не** появляется и рисовать чего не нужно никогда: страддл,
бомб-пот, «крутить дважды». Это свойство режима, а не настройка стола, —
соответствующие поля снапшота всегда `null`/`false`, и сервер таких
сообщений не примет.

Три новых экрана: **витрина турниров**, **карточка турнира** и
**турнирная панель** поверх обычного стола.

---

## 2. Витрина: топик `lobby`, категория `tournament`

Турниры живут в общем лобби отдельной категорией — как китайский покер.
Топик `lobby:tournament`.

```js
const channel = socket.channel("lobby:tournament", {
  game_types: [],
  currencies: [],
  table_sizes: [],
  limit_tiers: [],
  statuses: [],
  kinds: [],
  mine: false,
  has_ticket: false
})
```

### Фильтры

Первые четыре — те же, что в кэше. Три новых и два персональных:

* **`statuses`** — `announced` / `registering` / `running` / `late_reg` /
  `finished`. Главный турнирный фильтр: игрок спрашивает «куда можно
  войти прямо сейчас».
* **`kinds`** — `freeroll` (взнос 0), `rebuy` (ре-энтри разрешены),
  `bounty` (есть головы), `satellite` (платит билетами). Это
  **вычисляемые** признаки, а не поля: считает их сервер.
* **`limit_tiers`** — `micro` / `medium` / `high_roller`. В турнирах
  границы считаются **от цены входа**, а не от блайндов.
* **`mine`** — где я зарегистрирован. **`user_id` в payload не
  передаётся**: сервер берёт его из сокета. Не отправляйте его.
* **`has_ticket`** — куда пускает мой билет. Тоже персональный.

Пустой список означает «все», а не «ничего»: экран с ничем не отмеченным
фильтром обязан показывать весь пул.

### Порядок

**Сортирует сервер, пересортировывать не нужно.** Порядок: валюта
(`main` выше `play_money`) → **ближайший старт** → взнос. «Ближайший
старт» — главный порядок турнирной витрины: игрок выбирает, во что
успевает.

### Строка витрины

```
{
  tournament_id: "9f0fb02a-...",   // ИНСТАНС, не шаблон
  setting_id: "3c1d...",
  name: "Вечерний фрибай",
  description: "Ежедневно в 21:30",
  game_type: "texas_holdem",
  currency: "main",
  status: "registering",
  starts_at: "2026-09-01T18:30:00.000000Z",   // ВСЕГДА UTC
  buy_in: 1000,          // взнос, минимальные единицы
  entry_fee: 100,        // комиссия рума
  entry_price: 1100,     // сумма — ЕЁ и показывайте игроку
  starting_stack: 5000,  // ФИШКИ
  table_size: 6,
  min_players: 2,
  guarantee: 100000,     // 0 — без гарантии
  bounty_part: 0,        // >0 — баунти-турнир
  entries_count: 47,     // ВХОДЫ (с ре-энтри)
  players_count: 41,     // ЛЮДИ
  prize_pool: 47000,     // текущий фонд
  kinds: ["rebuy"],
  registered: false,     // я зарегистрирован
  has_ticket: true,      // мой билет сюда пускает
  visuals: { felt_color: "#1F4F7A", background_color: "#0B1A2A" }
}
```

**Ключевые ловушки этой структуры:**

1. **`tournament_id` — это инстанс, а не шаблон.** «Вечерний фрибай»
   сегодня и завтра — два разных `tournament_id` с одним `setting_id`.
   Регистрируетесь всегда в инстанс.
2. **`starts_at` — всегда UTC.** Рисуйте в местном времени игрока
   (`new Date(starts_at)`), а отсчёт считайте от него, а не от
   собственного таймера: игрок мог переключить вкладку на час.
3. **`entries_count` и `players_count` — разные числа.** 47 входов от 41
   человека означает шесть ре-энтри. Показывайте `players_count` как
   «участников», `entries_count` — как «входов». В сетке выплат считается
   `entries_count`.
4. **`entry_price` — то, что спишется.** `buy_in` и `entry_fee` показывайте
   раздельно только в подробностях.
5. **Взнос — деньги, стек — фишки** (задача 23). `entry_price` делится на
   100 у `main`, `starting_stack` печатается как есть.

### Гарантия и оверлей

Если `guarantee > 0` и `prize_pool` ещё не дотянул до неё, покажите
«гарантия N» — это обещание рума доплатить разницу. После старта
`prize_pool` фиксируется и больше не растёт.

### Обновления

```js
channel.on("lobby_delta", row => { /* та же форма, что строка витрины */ })
```

Приходит на регистрацию, вылет, смену статуса. Отсеянное вашим фильтром
до вас не доедет — сервер фильтрует адресно.

## 3. Карточка турнира

**Отдельный запрос, а не подписка:**

```js
channel.push("tournament_card", { tournament_id })
```

```
{
  tournament: { ... },        // как строка витрины, плюс:
  blind_levels: [
    { level: 1, small_blind: 25, big_blind: 50, ante: 0,
      duration_seconds: 600, label: "25/50",
      rebuy_allowed: true, addon_allowed: false },
    ...
  ],
  payouts: [                  // сетка ПРИ ТЕКУЩЕЙ ЯВКЕ
    { place: 1, amount: 30550, ticket: null },
    { place: 2, amount: 16450, ticket: null },
    { place: 3, amount: 4700,  ticket: { name: "Билет на воскресный главный", face_value: 5000 } }
  ],
  chip_counts: {              // ЧИПСЧЁТ С ПАГИНАЦИЕЙ
    entries: [
      { rank: 1, name: "player_17", stack: 42500, bounty: 400, place: null, status: "playing" },
      ...
    ],
    total: 41, offset: 0, limit: 50
  },
  registered: [ { name: "player_3" }, ... ]   // до старта — кто записан
}
```

**Карточка читается по нажатию и не пушится.** Это осознанное решение
сервера: при 300 участниках каждый вылет рассылал бы 300 строк каждому из
300 подключённых. Обновление — повторный запрос или кнопка «обновить»;
автообновление по таймеру чаще раза в 10–15 секунд не делайте.

`label` уровня приходит **готовым** — печатайте как есть. У Short Deck
блайндов нет вовсе, там придёт `"анте 100"` при `big_blind: 0`.

`payouts` считается **при текущей явке**: сетка привязана к диапазону
входов, и при 47 входах платят одно число мест, при 120 — другое. Не
кэшируйте её между запросами.

## 4. Регистрация

```js
channel.push("register", { tournament_id })                    // деньгами
channel.push("register", { tournament_id, pay_with: "ticket" }) // билетом
```

Клиент называет **только инстанс** и способ оплаты. Ни взноса, ни стека
в payload нет: выбирать нечего, суммы сервер берёт из шаблона.

Ответ:

```
{ entry_id: "...", entry_number: 1, starts_in_ms: 1800000 }
```

`entry_number` — какой это по счёту вход игрока. `1` — первичный,
`2` и дальше — ре-энтри.

**Регистрация не сажает за стол.** До старта стола ещё нет: вы получаете
подтверждение и ждёте `tournament_started`. Не пытайтесь сразу делать
`join` в топик стола.

### Билеты

Билет — вторая форма оплаты и вторая форма приза. У игрока их может быть
несколько; сервер гасит **самый скорый к истечению** и ровно один.

Кнопку «войти по билету» показывайте по `has_ticket: true` строки
витрины, но **право предъявить проверяет сервер в момент запроса**: между
«посмотрел» и «нажал» билет мог истечь. Ловите `ticket_required` и
предлагайте оплату деньгами.

Список билетов игрока приходит в кошельке (`wallet:<user_id>`):

```
tickets: [
  { id: "...", name: "Билет на воскресный главный",
    face_value: 5000, setting_id: "...", expires_at: "2026-10-01T00:00:00Z" }
]
```

`expires_at: null` — бессрочный. **Билеты сгорают**, и об истечении лучше
предупредить заранее: билет на выключённый оператором турнир перестаёт
работать и компенсации деньгами не имеет.

### Отмена до старта

```js
channel.push("unregister", { tournament_id })
```

Взнос и комиссия возвращаются целиком, билет — тоже. **После старта
отмена невозможна**: придёт `unregister_too_late`. Кнопку после старта
не показывайте.

### Ошибки регистрации

| Код | Что показать |
|---|---|
| `insufficient_funds` | не хватает на вход (взнос + комиссия — одной операцией) |
| `registration_closed` | регистрация ещё не открыта или уже закрыта |
| `tournament_full` | достигнут потолок участников или входов |
| `tournament_started` | турнир уже идёт, войти нельзя |
| `tournament_cancelled` | турнир отменён |
| `already_registered` | вы уже зарегистрированы |
| `unregister_too_late` | разрегистрироваться уже нельзя |
| `ticket_required` | годного билета нет |
| `reentry_not_allowed` | ре-энтри в этом турнире запрещены |
| `rebuy_limit_reached` | лимит повторных входов исчерпан |
| `addon_not_allowed` | аддон сейчас недоступен |

**`insufficient_funds` означает отказ целиком.** Ситуации «взнос списали,
на комиссию не хватило» не бывает: это одна транзакция.

## 5. Топик турнира: `tournament:<tournament_id>`

Отдельный канал рядом с каналом стола. Подписываться на него нужно
**с момента регистрации**, а не с момента посадки: через него приходят
и отсчёт до старта, и пересадки.

```js
const t = socket.channel(`tournament:${tournament_id}`, {})
```

### Снапшот `tournament_state`

```
{
  status: "running",
  starts_at: "2026-09-01T18:30:00.000000Z",
  level: 7,
  next_level_in_ms: 92000,      // null — уровень последний
  small_blind: 400, big_blind: 800, ante: 100,
  label: "400/800 (100)",
  players_left: 20,
  entries: 100,
  my_rank: 6,                   // моё место по стеку; null — я вылетел
  avg_stack: 25000,
  next_payout_place: 15,        // ближайшая призовая граница
  on_break: false,
  break_ends_in_ms: null,
  late_reg_until: "2026-09-01T20:10:00.000000Z",
  my_place: null,               // моё итоговое место, когда вылечу
  my_bounty: 400                // цена моей головы; 0 — не баунти
}
```

**Чего в снапшоте нет и не будет: списка участников и чипсчёта.** Это
решение сервера, а не недоработка: при 300 участниках каждый вылет
рассылал бы 300 строк каждому. Игроку за столом нужны четыре вещи сверх
собственного стола — уровень, сколько осталось, своё место по стеку и
ближайшая призовая граница, — и все они здесь счётчиками.

`20 / 100` читается прямо: осталось 20 из 100 **входов**.

Полный чипсчёт — только в карточке турнира, по требованию.

### События

```js
t.on("tournament_delta", d => { /* уровень, вылеты, перерыв */ })
t.on("tournament_started", d => { /* турнир начался */ })
t.on("table_changed", d => { /* d.table_id, d.seat — ПЕРЕСАДКА */ })
t.on("final_table", d => { /* d.table_id — финалка */ })
t.on("reentry_offer", d => { /* d.deadline_ms, d.cost, d.stack, d.left */ })
t.on("addon_offer", d => { /* d.deadline_ms, d.cost, d.stack */ })
t.on("tournament_result", d => { /* d.place, d.prize, d.bounties, d.ticket */ })
t.on("tournament_cancelled", d => { /* возврат сделан */ })
```

## 6. Пересадка — главная новая механика

```
"table_changed"  { table_id: "новый-uuid", seat: 4 }
```

Игрока перевели за другой стол. Обязанность клиента:

1. **Выйти из старого топика** `table:<старый>`.
2. **Зайти в новый** `table:<новый>` и отрисовать снапшот заново.
3. Показать короткое уведомление «вас пересадили за новый стол».

**Карт в руках в этот момент нет по построению** — сервер пересаживает
только между раздачами. Если вы видите пересадку с картами на руках, это
баг сервера, а не ситуация, которую надо обрабатывать.

`final_table` приходит, когда турнир схлопнулся до одного стола. Стол при
этом **перекрашивается**: приходит вторая пара цветов в `visuals`
снапшота стола (бордовое сукно вместо синего). Цвет берите из снапшота,
не из своей константы.

## 7. Перерывы

**Каждый час в `XX:55` турнир уходит на пятиминутный перерыв.** Это
правило рума, а не настройка: одинаково для всех турниров, чтобы игрок
за четырьмя столами получил один общий перерыв, а не четыре вразнобой.

```
"tournament_delta"  { on_break: true, break_ends_in_ms: 300000 }
```

Что нужно нарисовать:

* плашку «перерыв, до конца M:SS» поверх стола;
* **таймер уровня остановлен** — `next_level_in_ms` на перерыве не
  тикает. Не досчитывайте его сами;
* карты не раздаются, кнопок действий нет.

Тонкость, которую стоит понимать: **перерыв начинается позже `XX:55`**
ровно настолько, сколько доигрывалась самая долгая раздача в турнире, но
длится всегда полные пять минут. Не показывайте «перерыв в 21:55» как
точное время — показывайте «скоро перерыв», а плашку рисуйте по событию.

## 8. Ре-энтри и аддон

### Ре-энтри

Когда игрок вылетает, а уровень ещё разрешает вход:

```
"reentry_offer"  { deadline_ms: 30000, cost: 1100, stack: 5000, left: 2 }
```

```js
t.push("reentry", {})
```

Диалог с обратным отсчётом: «войти заново за N? осталось попыток: 2».
**Пока идёт отсчёт, место игроку не присвоено** — не показывайте
«вы заняли 34-е место», пока таймер не истёк или игрок не отказался.

`left` — сколько повторных входов ещё доступно **этому игроку**.

Игрок с фишками войти заново не может — это не докупка. Кнопку
показывайте только по событию.

### Аддон

```
"addon_offer"  { deadline_ms: 300000, cost: 500, stack: 5000 }
```

```js
t.push("addon", {})
```

Приходит **на перерыве** внутри уровня, где аддон разрешён. Окно аддона
открывается вместе с перерывом и закрывается вместе с ним: пять минут —
это и есть время на решение.

Аддон доступен даже игроку с нулевым стеком — это его последний шанс.

## 9. Баунти (PKO)

Если `bounty_part > 0`, турнир баунти-шный. Часть взноса каждого игрока
становится **ценой его головы**, и она выплачивается по ходу игры.

### Что рисовать за столом

**Цена головы каждого игрока публична** — без неё PKO не играется:
решение о колле зависит от того, сколько стоит соперник. В снапшоте стола
у каждого места появляется поле:

```
seats: [ { seat: 1, stack: 42500, bounty: 850, ... }, ... ]
```

Рисуйте её значком рядом со стеком. **Это деньги** (задача 23), а не
фишки: форматируется делением на 100 у `main`.

### Событие выбивания

```
"bounty_won"  { killer_seat: 3, victim_seat: 5, cash: 425, added_to_bounty: 425 }
```

Анимация: `cash` улетает в стек-панель убийцы деньгами, `added_to_bounty`
добавляется к его голове. **Суммы приходят посчитанными** — не делите
голову сами: правило деления живёт на сервере и меняется настройкой.

При фиксированном баунти `added_to_bounty` будет `0` — вся голова уходит
деньгами. Отдельной ветки для этого не нужно.

## 10. Итог турнира

```
"tournament_result"  {
  place: 12,
  prize: 4700,
  bounties: 1275,        // сколько голов собрано за турнир
  ticket: { name: "Билет на воскресный главный", face_value: 5000 }
}
```

`prize` и `bounties` — разные деньги и приходят разными записями в
кошелёк (`tournament_prize` и `tournament_bounty`). Головы начисляются
**сразу после раздачи**, приз за место — в конце турнира.

`ticket` не `null` — вместо денег (или вместе с ними) выдан билет; он
появится в списке билетов кошелька.

**Победитель забирает и собственную голову** — это часть финальной
выплаты, отдельного события не будет.

### Отмена турнира

```
"tournament_cancelled"  { refunded: 1100, ticket_returned: true }
```

Турнир не набрал минимума. Взнос и комиссия вернулись, билет — тоже.
**Гарантия при отмене не выплачивается**: GTD обещает размер фонда
состоявшегося турнира.

## 11. Новые записи в кошельке

К задаче 18 добавляются типы (задача 23 — форматирование сумм):

| Тип | Знак | Что это |
|---|---|---|
| `tournament_entry` | − | взнос за турнир |
| `tournament_fee` | − | комиссия рума |
| `tournament_rebuy` | − | повторный вход |
| `tournament_addon` | − | аддон |
| `tournament_prize` | + | приз за место |
| `tournament_bounty` | + | выбитая голова |
| `tournament_refund` | + | возврат при отмене |

Взнос и комиссия приходят **двумя записями** на одну регистрацию — так
игрок видит, сколько ушло в фонд, а сколько руму. Показывайте их
раздельно, не схлопывайте в одну строку.

## 12. Чеклист

**Витрина**
- [ ] топик `lobby:tournament`, фильтры включая `statuses`, `kinds`, `mine`, `has_ticket`
- [ ] `user_id` в payload фильтров **не** передаётся
- [ ] порядок сервера не пересортировывается
- [ ] `starts_at` рисуется в местном времени, отсчёт — от него
- [ ] `entries_count` и `players_count` показаны как разные числа
- [ ] `entry_price` — то, что спишется; взнос и комиссия раздельно в подробностях

**Карточка**
- [ ] запрос `tournament_card`, не подписка
- [ ] чипсчёт с пагинацией, обновление по кнопке (не чаще 10–15 с)
- [ ] `label` уровня печатается готовым
- [ ] сетка выплат не кэшируется между запросами

**Регистрация**
- [ ] деньгами и билетом, `pay_with: "ticket"`
- [ ] регистрация не сажает за стол — ждём `tournament_started`
- [ ] отмена скрыта после старта
- [ ] все коды ошибок §4 обработаны

**Стол и турнир**
- [ ] подписка на `tournament:<id>` с момента регистрации
- [ ] `table_changed` — выход из старого топика, вход в новый
- [ ] `final_table` — перекраска из снапшота, не из константы
- [ ] панель: уровень, до повышения, осталось/входов, моё место, до денег
- [ ] перерыв: плашка, остановленный таймер уровня
- [ ] `reentry_offer` / `addon_offer` с обратным отсчётом
- [ ] место не показывается, пока идёт окно ре-энтри

**Баунти**
- [ ] `bounty` у каждого места в снапшоте стола, форматируется как деньги
- [ ] анимация `bounty_won` по готовым суммам
- [ ] `added_to_bounty: 0` не требует отдельной ветки

**Чего быть не должно**
- [ ] страддла, бомб-пота, «крутить дважды» в турнирном столе
- [ ] расчёта призов, мест, фонда и цены головы на клиенте
- [ ] пересчёта `next_level_in_ms` на перерыве
