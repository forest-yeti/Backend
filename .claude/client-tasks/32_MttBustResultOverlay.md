# Клиент. Задача 32. MTT: экран вылета — своё место и число участников

Дополнение к [задаче 30](30_Tournaments.md). Не про сервер: вся
сантехника для этого экрана уже доставляется, не хватает только самого
экрана. Бэкенд в этой задаче не меняется.

## 1. Чего не хватает

Победитель турнира видит итог (`tournament_finished`, задача 30 §10).
Игрок, который вылетел **не последним**, сейчас не видит ничего похожего:
его место присваивается (`player_busted`), но глазами клиента это просто
тихо освобождает стек — своего экрана «вы заняли N место» нет.

Просьба — минимум для начала: небольшой оверлей вроде

```
Ваше место — 5
Всего участников — 399
```

## 2. Всё нужное уже едет, не хватает только UI

Проверено по коду главного процесса (`src/main/mtt.ts`):

* `player_busted` (`{ entry_id, place, prize, bounty_earned }`) уже
  пересылается **и** в окно турнира, **и** в окно каждого стола турнира —
  `sendEvent` рассылает событие через `IPC.MttEventChannel` в
  `windowForTournament` и в `windowForRoom` для каждого `roomId` из
  `instance.tables` (задача 30 §5, раздел «события»).
* Число участников уже едет тем же путём: `pushState` шлёт **весь**
  `MttWindowState` (включая `row.entries_count`) в те же окна через
  `IPC.MttState`, при каждом обновлении карточки.

Значит, окну стола, за которым игрок только что вылетел, для этого
экрана **не нужен ни новый запрос, ни новое событие** — оба числа уже
приходят в тот же рендерер, где сейчас рисуется стол. Не хватает только
подписки на `player_busted` (через `onEvent`, как уже сделано для
`addon`/офферов в `MttPanel.tsx`) и самого компонента.

## 3. Что показывать и когда

* Слушать `MttEvent` с `kind === 'player_busted'`.
* Показывать оверлей **только если `event.entry_id === state.entry_id`**
  (`state` — то, что уже даёт `useMtt`). Событие широковещательное: все
  подписчики топика турнира видят вылет любого игрока, не только своего
  — без фильтра оверлей будет всплывать на каждом чужом вылете.
* `place`, `prize` и `bounty_earned` — из события, считать их не нужно.
  `entries_count` — из `state.row?.entries_count` на тот момент (то же
  поле, что и в строке витрины).
* `prize` — выплата за место по сетке при текущей явке, в минимальных
  единицах; ноль означает место вне призов, показывайте прочерк.
  `bounty_earned` — заработанное на **чужих** головах, в небаунти-турнире
  всегда `0` (в таком турнире строку просто не рисуйте). Ни то, ни другое
  не является подтверждением зачисления — деньги придут записями в
  кошелёк, см. [задачу 18](18_WalletChannel.md).
* На саттелитах `prize` будет нулевым и там, где место оплачивается
  билетом: номинал в это событие не попадает (задача 30 §5). Если
  режим саттелитов дойдёт до UI — берите итог из `tournament_finished`.
* `player_busted` по протоколу и так приходит только на **окончательный**
  вылет (задача 30, таблица событий: «окончательный вылет, место
  присвоено»). Пока для входа открыто окно ре-энтри, вместо этого
  события идёт `reentry_offer` — отдельно фильтровать «а не идёт ли ещё
  ре-энтри» на клиенте не нужно.

## 4. Известное ограничение первой версии

`entries_count` в этот момент — счётчик **на сейчас**, а не окончательный
итог турнира: пока не закрылась поздняя регистрация, число входов может
ещё вырасти за счёт чужих ре-энтри уже после вашего вылета. Для первой
версии это ожидаемо и достаточно (с пометкой «на момент вылета» в тексте,
если понадобится) — точный финальный «из скольких» по всему турниру
считать сразу не нужно, это можно отложить отдельной задачей при
необходимости.

Ровно то же и с `prize`: сетка считается от **текущей** явки, и до
закрытия поздней регистрации сумма может ещё сдвинуться. Правка сетки
турнира админом её не сдвинет — идущий инстанс считается по снапшоту,
снятому при открытии регистрации.

## 5. Отличие от итога турнира

В отличие от `TournamentResults` (задача 26/30), стол в этом случае
**не закрывается**: игрок вылетел, но турнир продолжается на этом же или
других столах, и место могут занять другие (или снапшот стола просто
покажет пустое место). Оверлей — поверх текущего вида стола, закрывается
по таймауту или по действию игрока (выбор конкретного UX — за
разработчиком клиента), но не должен требовать выхода из окна.

## Чеклист

- [ ] подписка на `player_busted` в окне стола, фильтр по своему `entry_id`
- [ ] оверлей: место, `prize` и `bounty_earned` из события; число участников из `state.row.entries_count`
- [ ] `prize: 0` — прочерк, а не «0.00»; `bounty_earned: 0` — строки нет
- [ ] не показывается на чужих вылетах (широковещательность события)
- [ ] не путается с `reentry_offer` — на этот момент вылет уже окончателен
- [ ] стол при этом не закрывается и не требует навигации
