# Клиент. Задача 26. Sit & Go: гипер-турниры со случайным призом

Документ для разработчика Electron-клиента. Новый режим игры рядом с
кэшем. Дополняет [задачу 2](2_CashGame.md), [задачу 3](3_Hand.md),
[задачу 4](4_LobbyFilters.md) и [задачу 23](23_MoneyUnits.md).

Sit & Go — турнир на фиксированное число игроков, который начинается,
как только собрался состав. Играется до последнего оставшегося. Призовой
фонд **разыгрывается случайно** перед первой раздачей: множитель к взносу
тянется из таблицы и объявляется всем сразу.

Механика целиком серверная. Клиент не считает призы, не поднимает
блайнды, не решает, кто вылетел, и не определяет победителя — он рисует
то, что пришло.

---

## 1. Чем турнир отличается от кэша

Одно отличие порождает все остальные: **фишка в турнире — не деньги,
а позиция в структуре мест.** Её нельзя купить, докупить или унести
со стола.

| | Кэш | Sit & Go |
|---|---|---|
| Столы | 2..9 мест | 2-max, 3-max и 6-max |
| Вход | бай-ин в границах, игрок выбирает сумму | фиксированный взнос, выбора нет |
| Старт | со второго игрока | только полным составом |
| Стек кончился | предложение докупиться | вылет |
| Встать из-за стола | между раздачами | нельзя после старта |
| Блайнды | постоянные | растут по расписанию |
| Выигрыш | забрал со стола cash-out'ом | приз за место |
| Страддл | есть | **нет** |
| Бомб-пот | есть | **нет** |
| Крутить дважды | есть | **нет** |

Последние три строки — не настройка стола, а свойство режима. Кнопок,
плашек и диалогов для них в турнире рисовать не нужно **никогда**:
соответствующие поля снапшота всегда `null`/`false`, а сервер таких
сообщений не примет.

Отдельного канала для игры нет: **турнирный стол живёт в обычном топике
`table:<room_id>`**. Всё, что вы уже написали для кэш-стола — карты,
торги, тайм-банк, чат, реакции, — работает без изменений.

## 2. Витрина: топик `sit_n_go`

Отдельный топик рядом с `lobby`. Кэш и турниры не смешиваются в одном
списке — это разные экраны.

### Подписка

```js
const channel = socket.channel("sit_n_go", { game_types: [] })
```

`game_types` — фильтр по дисциплине, **множественный выбор**. Пустой
список означает «все», а не «ничего»: экран с ничем не отмеченным
фильтром обязан показывать весь пул.

Незнакомая серверу дисциплина отбрасывается молча — витрина придёт без
неё, а не с ошибкой.

### Ответ на join и на `list`

```
{
  tournaments: [ ... ],           // строки витрины, см. ниже
  filters: {
    game_types: ["texas_holdem", "short_deck"]
  }
}
```

`filters.game_types` — список доступных дисциплин **с сервера**.
Рисуйте панель фильтра по нему, а не по захардкоженному списку: новый
вид покера не должен требовать релиза клиента.

### Строка витрины

```
{
  setting_id: "9f0fb02a-...",
  name: "Hold'em Hyper 3-Max $1.00",
  game_type: "texas_holdem",
  currency: "main",
  betting_structure: "blinds",   // или "button_ante" у Short Deck
  buy_in: 100,                   // взнос в МИНИМАЛЬНЫХ единицах: $1.00
  starting_stack: 500,           // стартовый стек в ФИШКАХ
  max_players: 3,
  registered: 2,                 // уже зарегистрировано в набираемый турнир
  running: 1,                    // сколько турниров этого шаблона идёт сейчас
  blind_levels: [ ... ],
  prize_tiers: [ ... ],
  visuals: { felt_color: "#9A7A2E", background_color: "#151006" }
}
```

**`buy_in` и `starting_stack` — разные шкалы, и путать их нельзя.**
Взнос форматируется как деньги (задача 23: `main` — делить на 100),
стартовый стек печатается как есть — это фишки, а не деньги, и в кошелёк
они не превращаются.

`visuals` — те же поля, что у кэш-стола: цвет сукна и фон комнаты.
Турнирные столы **золотые**, кэшевые зелёные: цвет и есть первый признак,
по которому режим опознаётся с одного взгляда. Берите его из снапшота,
а не из своей константы — оператор волен перекрасить конкретный стол,
и захардкоженное золото тогда разойдётся с сервером.

### Уровни

```
blind_levels: [
  { level: 1, small_blind: 10, big_blind: 20, ante: 0,
    duration_seconds: 180, label: "10/20" },
  ...
]
```

`label` приходит **готовым**. Печатайте его как есть и не собирайте
строку сами: у Short Deck блайндов нет вовсе, и там придёт `"анте 10"`
при `big_blind: 0`. Решать, какие поля показывать, — значит знать, какая
структура ставок у какой дисциплины; это знание живёт на сервере.

### Призовые тиры

```
prize_tiers: [
  { multiplier: 200,     label: "x2",     chance_ppm: 720250, payouts: [100] },
  { multiplier: 2500,    label: "x25",    chance_ppm:    900, payouts: [80, 20] },
  { multiplier: 1000000, label: "x10000", chance_ppm:      1, payouts: [75, 20, 5] }
]
```

* `multiplier` — множитель в **сотых долях**: `250` = x2.5. У столов на
  двоих он бывает **меньше x2** (`150` = x1.5) — это не ошибка данных:
  матожидание множителя равно числу участников, умноженному на возврат,
  и для двоих оно ниже двух. Не отсеивайте такие тиры и не считайте их
  «проигрышными».
* `label` — готовая подпись (`"x2.5"`). Печатайте её, а не делите сами.
* `chance_ppm` — шанс в **миллионных долях**: `720250` = 72.025%,
  `1` = 0.0001%. Это шкала барабана, а не проценты.
* `payouts` — доли мест в процентах, первым победитель. Длина списка
  и есть число оплачиваемых мест этого тира.

Из таблицы строится экран «за что играем»: список множителей с их
шансами. Это же — барабан анимации розыгрыша.

### Обновления

```
channel.on("sit_n_go_delta", row => { /* та же форма, что строка витрины */ })
```

Приходит, когда меняется число зарегистрированных или запускается новый
турнир. Строка, отсеянная вашим фильтром, до вас не доедет — сервер
фильтрует адресно.

## 3. Регистрация

```js
channel.push("register", { setting_id })
```

Клиент называет **только шаблон**. Ни взноса, ни стека в payload нет и
быть не может: выбирать нечего, все входят одинаково, а суммы сервер
берёт из шаблона.

Ответ — как у посадки за кэш-стол:

```
{ room_id: "...", seat: 2, stack: 500 }
```

Дальше — обычный `join` в топик `table:<room_id>`.

### Отмена до старта

```js
channel.push("unregister", { room_id })
```

Взнос возвращается в кошелёк целиком. **После старта отмена невозможна**
— придёт `hand_in_progress`. Кнопку «отменить» после первой раздачи
показывать не нужно.

Право отменить проверяет сервер в момент запроса: не решайте это по
снапшоту, между «посмотрел» и «нажал» турнир успевает начаться.

### Ошибки

| Код | Что показать |
|---|---|
| `insufficient_funds` | не хватает на взнос |
| `no_seats_available` | турнир только что заполнился, попробуйте снова |
| `already_seated` | вы уже зарегистрированы |
| `hand_in_progress` | турнир начался, отмена невозможна |
| `not_found` | шаблон или комната не найдены |

## 4. Стол: что нового в снапшоте

Всё, что было в кэш-столе, остаётся. Добавляется **один блок в корне**:

```
tournament: {
  level: 1,                   // текущий уровень структуры
  next_level_in_ms: 179990,   // до повышения; null — уровень последний
  prize: {                    // null, пока турнир не начался
    multiplier: 200,
    label: "x2",
    pool: 200,                // фонд в МИНИМАЛЬНЫХ единицах
    payouts: [100]
  },
  buy_in: 100,
  starting_stack: 500,
  players_left: 3,            // сколько ещё не вылетело
  standings: [ ... ],         // занятые места, см. §6
  finished: false
}
```

**`tournament: null` означает «это кэш-стол».** Ветвитесь по наличию
блока, а не по полям внутри него.

`small_blind`, `big_blind` и `ante` в корне снапшота — это номиналы
**текущего уровня**, а не шаблона. Читайте их оттуда же, откуда читали
для кэша: они уже посчитаны.

### Тайминги

`timings` у турнира содержит меньше ключей, чем у кэша:

```
{ action_timeout_ms, time_bank_ms, time_bank_refill,
  disconnect_grace_ms, prize_reveal_ms }
```

`rebuy_prompt_ms`, `sit_out_timeout_ms` и `straddle_offer_ms`
**отсутствуют**, потому что этих механик в турнире нет. Не подставляйте
вместо них нули — иначе нарисуете счётчик несуществующего таймера.
Проверяйте наличие ключа.

## 5. События турнира

Приходят в топик стола рядом с обычными событиями раздачи.

| Событие | Когда | Payload |
|---|---|---|
| `prize_revealed` | до первой карты, один раз за турнир | `{multiplier, label, pool, payouts}` |
| `level_up` | блайнды выросли, между раздачами | `{level, small_blind, big_blind, ante, next_level_in_ms}` |
| `tournament_finished` | остался один игрок | `{prize, results}` |

### `prize_revealed` — главный момент режима

Приходит **до того, как игрок увидел первую карту**. Это и есть смысл
механики: сначала узнаёшь, за что играешь, потом играешь.

Здесь уместна заметная анимация — барабан по `prize_tiers` из витрины,
останавливающийся на выпавшем `multiplier`. Длительность возьмите из
`timings.prize_reveal_ms`: сервер выдержит эту паузу перед раздачей.

Пропускать событие нельзя: другого способа узнать призовой фонд у игрока
нет. Подключившийся позже возьмёт его из снапшота (`tournament.prize`).

### `level_up`

Блайнды растут **между раздачами**, никогда посреди улицы. Событие
приходит перед стартом следующей раздачи.

Уместна короткая плашка «Уровень 2 — 15/30». `next_level_in_ms` — остаток
до следующего повышения; `null` означает, что уровень последний и расти
больше некуда — счётчик тогда не рисуйте.

Обратный отсчёт ведите от полученного значения локально, не опрашивая
сервер. При реконнекте свежий остаток придёт в снапшоте.

## 6. Конец турнира

```
tournament_finished: {
  prize: { multiplier, label, pool, payouts },
  results: [
    { user_id: "...", seat: 1, place: 1, amount: 750 },
    { user_id: "...", seat: 3, place: 2, amount: 200 },
    { user_id: "...", seat: 2, place: 3, amount: 50 }
  ]
}
```

* `place` — занятое место, `1` у победителя. Список отсортирован по нему.
* `amount` — выплата в **минимальных единицах**. Ноль означает место вне
  призовой зоны; это не ошибка, показывайте прочерк, а не «0.00».
* Сумма всех `amount` равна `prize.pool` **ровно**.

Итоговая таблица показывается около 15 секунд, после чего стол
закрывается и топик перестаёт существовать. Закройте окно стола сами
по этому событию — не ждите разрыва канала.

Деньги приходят в кошелёк отдельно, обычным событием
[кошелькового канала](18_WalletChannel.md) с типом записи `prize`.
Баланс берите оттуда, а не из `amount`: `results` — это результат
турнира, а не подтверждение зачисления.

### Вылет

Вылетевший игрок **остаётся за столом зрителем** — место не
освобождается, и в `seats` он виден с нулевым стеком. Это не баг: в
Sit & Go сажать на его место некого, состав набран до старта.

Показывайте таких игроков затенёнными, с их местом из
`tournament.standings`:

```
standings: [ { seat: 2, user_id: "...", place: 3 } ]
```

Список ведётся в порядке вылета, последний выбывший первым. Победителя
в нём нет до самого конца — пока живых больше одного, первого места не
существует, и рисовать его заранее нельзя.

## 7. Чего делать не нужно

Список короткий, но каждый пункт — это соблазн, который ломает режим:

* **Не считать призы.** `pool` и `amount` приходят посчитанными.
  Умножать `buy_in` на `multiplier` самому — значит завести вторую копию
  доменного правила, которая разойдётся с сервером на округлении.
* **Не поднимать блайнды по таймеру.** Уровень меняет сервер, событием.
  Локальный таймер разойдётся с ним на первой же затянутой раздаче.
* **Не определять победителя.** «У всех, кроме одного, стек ноль» — это
  ваша догадка, а не факт турнира. Факт приходит в
  `tournament_finished`.
* **Не показывать кнопки страддла, бомб-пота и «крутить дважды».**
  Их в турнире нет; сервер такие сообщения отвергнет.
* **Не предлагать докупку** при нулевом стеке. В турнире это вылет,
  а не повод достать кошелёк.
* **Не освобождать место вылетевшего** в своей модели стола: сервер его
  не освобождает, и ваша картинка разойдётся со снапшотом.

## 8. Чек-лист

- [ ] Экран Sit & Go отдельно от кэш-лобби, топик `sit_n_go`.
- [ ] Цвета стола и лобби берутся из `visuals`, а не зашиты в клиент.
- [ ] Фильтр по дисциплине с множественным выбором; пустой = все;
      список дисциплин берётся из `filters.game_types`.
- [ ] Взнос форматируется как деньги, стартовый стек — как фишки.
- [ ] `label` уровней и множителей печатается как есть.
- [ ] Экран «за что играем» строится из `prize_tiers`.
- [ ] `register` шлёт только `setting_id`.
- [ ] Кнопка отмены есть до старта и исчезает после.
- [ ] Анимация `prize_revealed` укладывается в `prize_reveal_ms`.
- [ ] Плашка `level_up` и счётчик до следующего уровня (скрыт при `null`).
- [ ] Вылетевшие показаны затенёнными, с местом, и не исчезают со стола.
- [ ] Итоговая таблица по `tournament_finished`, окно закрывается само.
- [ ] Ключи `timings` проверяются на наличие, а не подставляются нулями.
- [ ] Ни одной кнопки страддла, бомб-пота и run it twice за турнирным столом.
