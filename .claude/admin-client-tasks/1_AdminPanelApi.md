# Админ-клиент. Задача 1. API и каналы панели

Документ для разработчика Vue-приложения панели администратора. Описывает
**всё**, что сервер отдаёт панели: HTTP-ручки, сокет, форматы, коды ошибок
и правила, которые клиент обязан соблюдать.

Панель — отдельное приложение. Бэкенд её не собирает и не раздаёт.

---

## 1. Два транспорта и почему их два

| Что | Куда | Почему так |
|---|---|---|
| Логин, списки, деньги, журнал | HTTP `/admin/*` | чтение с пагинацией и транзакционная запись |
| Живой список игр, наблюдение за столом, ход турнира | WebSocket `/admin/socket` | сервер пушит сам |

Игровой сокет (`/socket`) панель не открывает **никогда**. Это не
рекомендация: соли токенов разные, и игровой токен физически не пройдёт
проверку в `/admin/*`, а админский — в игре.

## 2. Аутентификация

### Вход

```http
POST /admin/auth/login
Content-Type: application/json

{"email": "admin@example.com", "password": "..."}
```

Ответ `200`:

```json
{
  "access": "SFMyNTY...",
  "refresh": "9xJk...",
  "expires_in": 900,
  "admin": {"id": "uuid", "name": "Admin", "email": "...", "avatar": "First", "role": "admin"},
  "session": {
    "id": "uuid",
    "ip": "10.0.0.1",
    "user_agent": "Mozilla/5.0 ...",
    "expires_at": "2026-08-25T22:00:00.000000Z",
    "last_seen_at": "2026-08-25T10:00:00.000000Z",
    "inserted_at": "2026-08-25T10:00:00.000000Z",
    "current": true
  }
}
```

* `access` — **15 минут**, живёт только в памяти Pinia;
* `refresh` — **12 часов**, в `sessionStorage`, то есть умирает с вкладкой.
  `localStorage` не используется;
* учётка не админа получает тот же `401 invalid_credentials`, что и
  неверный пароль. Панель не должна пытаться по ответу выяснить, «есть ли
  такой админ» — сервер намеренно отвечает одинаково.

### Продление

```http
POST /admin/auth/refresh
{"refresh": "9xJk..."}
```

Ответ — **новая пара**. Предъявленный `refresh` отзывается немедленно: он
одноразовый, и повторная отправка того же значения вернёт
`admin_session_expired`.

Обновлять `access` за **60 секунд** до истечения. При неудаче — очистить
стор и уйти на экран логина; повторять запрос по кругу нельзя.

### Выход и «кто я»

```http
POST /admin/auth/logout        # отзывает текущую сессию
GET  /admin/auth/me
```

`GET /admin/auth/me`:

```json
{
  "admin": {"id": "...", "name": "...", "email": "...", "role": "admin",
            "status": "active", "avatar": "First",
            "wallets": {"main": 0, "play_money": 10000}},
  "sessions": [{"id": "...", "ip": "...", "current": true, "...": "..."}],
  "observer_enabled": false
}
```

`observer_enabled: false` означает, что наблюдение за столами выключено
конфигом сервера. В этом случае **вкладка «Стол» не показывается вовсе** —
не показывается серой, не показывается с ошибкой: её нет.

### Каждый запрос

```
Authorization: Bearer <access>
```

Токен — только в заголовке. В query-параметре его быть не должно: строка
запроса попадает в логи прокси и в историю браузера.

## 3. Ошибки

Ответ всегда одной формы:

```json
{"code": "admin_reason_required", "message": "Нужно указать причину"}
```

Ветвиться **по `code`**, показывать человеку `message`. Свободного текста
в `code` не бывает.

| Код | HTTP | Что значит |
|---|---|---|
| `token_invalid` / `token_expired` | 401 | токена нет, он чужой или протух |
| `admin_session_expired` | 401 | сессия отозвана или истекла — на логин |
| `admin_required` | 403 | у учётки нет роли админа |
| `admin_reason_required` | 422 | причина пустая или короче 3 символов |
| `admin_amount_invalid` | 422 | сумма не целая или не положительная |
| `admin_insufficient_funds` | 422 | на кошельке игрока меньше, чем списывают |
| `admin_self_target` | 422 | себе начислять и списывать нельзя |
| `admin_room_not_found` | 404 | комнаты или турнира нет |
| `admin_observer_disabled` | 403 | наблюдение выключено конфигом |
| `validation_failed` | 422 | форма запроса не прошла разбор |
| `rate_limited` | 429 | 5 попыток входа за 15 минут исчерпаны |
| `not_found` | 404 | нет такого игрока |

## 4. Пагинация

Везде одинаковая, **курсорная**:

```
?limit=50&cursor=<строка из прошлого ответа>
```

* `limit` ≤ 100, по умолчанию 50;
* `cursor` — **непрозрачная строка**. Не разбирать, не собирать, не
  сравнивать: вернуть ровно то, что пришло;
* `cursor: null` в ответе означает «страниц больше нет»;
* смена сортировки или фильтра начинает список **заново**, курсор старой
  выборки к новой не применяется.

Ответ списка:

```json
{"items": [...], "cursor": "eyJ..." }
```

## 5. Люди

### Список

```
GET /admin/users?cursor=&limit=&q=&status=&role=&sort=&verify=
```

* `q` — подстрока ника **или** email;
* `status` — `active` / `blocked`;
* `role` — `default` / `admin`;
* `sort` — `registered_at` (по умолчанию), `name`, `balance`;
* `verify=true` — добавляет к каждой строке сверку кэша баланса с журналом.
  Считается дополнительным запросом, поэтому по умолчанию выключена:
  включать на карточке и по кнопке, а не на каждой странице списка.

Строка:

```json
{
  "id": "uuid",
  "name": "Player",
  "email": "p@example.com",
  "status": "active",
  "role": "default",
  "avatar": "First",
  "flair": "default",
  "wallets": {"main": 1250000, "play_money": 9800},
  "seated_at": [
    {"room_id": "uuid", "setting_id": "uuid", "seat": 2, "stack": 18400, "status": "playing"}
  ],
  "registered_at": "2026-08-01T10:00:00.000000Z",
  "verify": {"ledger": {"main": 1250000, "play_money": 9800}, "matches": true}
}
```

`verify.matches: false` — расхождение кэша и журнала. Это **инцидент**, а
не косметика: подсветить строку красным и не прятать.

`seated_at` — где игрок сидит **прямо сейчас**, по живым комнатам. Пустой
список не означает «оффлайн»: закрытое окно стола место не освобождает,
но и не всякий онлайн сидит за столом.

### Карточка и выписка

```
GET /admin/users/:id
GET /admin/users/:id/ledger?cursor=&limit=&currency=
```

Карточка — та же строка плюс `bans`:

```json
{"bans": [{"action": "ban_user", "reason": "мультиаккаунт",
           "at": "...", "admin": {"id": "...", "name": "Admin"}}]}
```

Выписка (курсор здесь — число, но правило то же: вернуть как пришло):

```json
{"items": [{"id": "uuid", "seq": 812, "currency": "play_money",
            "amount": -400, "type": "buy_in", "balance_after": 9600,
            "ref_id": "...", "at": "..."}],
 "cursor": "801"}
```

`amount` знаковый: минус — списание. Типы, которые оставляет панель, —
`admin_credit` и `admin_transfer`; `adjustment` означает техническую
коррекцию и к действиям админа отношения не имеет.

## 6. Деньги

Четыре мутирующих действия, у всех **обязательная причина** 3..500
символов:

```http
POST /admin/users/:id/ban      {"reason": "..."}
POST /admin/users/:id/unban    {"reason": "..."}
POST /admin/users/:id/credit   {"currency": "main", "amount": 100000,
                                "reason": "...", "idempotency_key": "uuid"}
POST /admin/users/:id/take     {"currency": "main", "amount": 100000,
                                "reason": "...", "idempotency_key": "uuid"}
```

### Правила, которые обязан соблюдать клиент

1. **`amount` — целое в минимальных единицах.** Никаких `float`. Человек
   вводит `1250.00`, в API уходит `125000`. Конвертация — **одно место**
   в коде, покрытое юнит-тестом.
2. **`idempotency_key` генерируется UUID'ом при открытии формы, а не при
   отправке.** Повторный клик по «Начислить» с той же формы — это тот же
   ключ, и сервер погасит второе начисление. Новый ключ на повторной
   отправке означает второе начисление вместо защиты от него.
3. Ответ на повтор — `200` с `{"repeated": true, ...}`. Это **успех**:
   операция уже выполнена. Показывать как выполненную, а не как ошибку.
4. Модалка обязана требовать причину и подтверждение суммы прописью.

Ответы:

```json
// credit
{"balance": 1350000, "currency": "main", "audit_id": "uuid"}
// take
{"player_balance": 1150000, "admin_balance": 100000,
 "currency": "main", "audit_id": "uuid"}
// ban / unban
{"id": "uuid", "status": "blocked"}
```

### Чего панель не делает

* **Не трогает фишки, которые сейчас на столе.** Списывается только то,
  что в кошельке. Если у игрока непустой `seated_at`, форма обязана
  показать предупреждение «в игре: N» — но сумма операции всё равно
  относится только к кошельку.
* **Не начисляет себе.** `admin_self_target` — не ошибка ввода, а
  запрет: свой кошелёк правится `mix`-задачей, где это видно в истории
  команд. Кнопки на своей карточке должны быть спрятаны, а не выдавать
  ошибку.

## 7. Игры

```
GET /admin/games?kind=cash|sit_and_go|mtt|ofc_cash|all
GET /admin/games/:kind/:id
```

Один список на все четыре режима, различаются полем `kind`. Четырёх
вкладок в UI это не отменяет — но за ними одна ручка и один фильтр.

```json
{
  "kind": "cash",
  "id": "uuid",
  "setting_id": "uuid",
  "name": "NL2 6-max",
  "game_type": "texas_holdem",
  "discipline": "holdem",
  "currency": "main",
  "status": "running",
  "players": 4,
  "seats": 6,
  "pot": 3400,
  "hand_no": 128,
  "observable": true,
  "participants": [
    {"user_id": "uuid", "name": "Player", "seat": 2,
     "stack": 18400, "status": "playing", "acting": true}
  ],
  "extra": {
    "limits": {"small_blind": 1, "big_blind": 2, "ante": 0},
    "bet_unit": 2,
    "buy_in": null,
    "starting_stack": null,
    "code": null,
    "tournament": null
  }
}
```

* `status` — `waiting` (набирается), `running` (играют), `closing`
  (закрывается). У турнира здесь его собственный статус;
* `pot: null` — банка нет: раздача не идёт либо это китайский покер, где
  банка не бывает вовсе. Рисовать `0` нельзя, это разные вещи;
* `observable: false` у строк `kind: "mtt"` — наблюдать можно за **столом**
  турнира, а не за турниром: карты у столов. Столы идущего MTT приходят в
  том же списке отдельными строками;
* `extra` собирается сервером. Клиент его **только показывает**: считать
  из него новые величины (например, «сколько всего фишек в игре») нельзя —
  если такое число нужно, оно должно приехать с сервера.

Турнирный `extra`:

```json
{"level": 7, "limits": {...}, "next_level_in_ms": 214000,
 "on_break": false, "break_ends_in_ms": null, "tables": 6, "entries": 54,
 "paid_places": 9, "final_table": false, "prize_pool": 108000,
 "started_at": "..."}
```

Все `*_in_ms` — **остатки**, а не моменты времени. Их нельзя сравнивать с
часами браузера: отсчитывать локально от момента получения.

## 8. Журнал

```
GET /admin/audit?cursor=&limit=&admin_id=&action=&subject_type=&subject_id=
```

```json
{"id": "uuid", "action": "credit", "subject_type": "wallet",
 "subject_id": "uuid", "amount": 100000, "currency": "main",
 "reason": "компенсация бага", "meta": {"user_id": "uuid", "before": 0, "after": 100000},
 "ip": "10.0.0.1", "at": "...",
 "admin": {"id": "uuid", "name": "Admin"}}
```

`action`: `login`, `login_failed`, `logout`, `ban_user`, `unban_user`,
`credit`, `debit_to_admin`, `observe_room_open`, `observe_room_close`,
`force_close_room`, `pause_tournament`, `resume_tournament`,
`cancel_tournament`.

Журнал **только на чтение**. Ручки «удалить запись» нет и не будет.

## 9. Сокет

```
wss://<host>/admin/socket/websocket?token=<access>&protocol_vsn=1
```

Библиотека — обычный `phoenix` js-клиент. Токен — тот же `access`, что и
на HTTP; при его обновлении соединение нужно пересоздать.

Отказ в handshake приходит телом `{"code": "...", "message": "..."}`:
`token_expired` — продлить пару и переподключиться, `admin_session_expired`
— уйти на логин.

Соединение перепроверяет сессию **раз в минуту**. Если сессию отозвали,
канал пришлёт `error` с `admin_session_expired` и закроется: это сигнал
уйти на логин, а не переподключаться.

### `admin:games`

Ответ на join — `{"items": [...]}`, тот же формат, что у HTTP.

| Направление | Сообщение | Payload |
|---|---|---|
| → | `list` | `{"kind": "cash"}` — ответ `{"items": [...]}` |
| → | `ping` | замер задержки |
| ← | `games` | `{"items": [...]}` — **полный** список заново |

`games` приходит целиком, а не дельтой: заменять состояние, а не мержить.

### `admin:room:<room_id>` — god-mode

**Временный отладочный режим.** Он вырезается перед публичным релизом
целиком, поэтому его код в клиенте должен жить отдельно и не прорастать
в остальные экраны.

Join отвечает:

```json
{"room": { ... полный снапшот ... },
 "feed": [ ... последние события ... ]}
```

`room` — несфильтрованное состояние стола: стеки, борд, банк, **все**
карманные карты всех игроков и остаток колоды.

```json
{"hand": {"street": "flop", "pot": 300, "board": [{"rank": 14, "suit": "s"}],
          "hole_cards": {"1": [{"rank": 7, "suit": "d"}, ...],
                         "2": [...]},
          "deck": [ ... ]}}
```

Seed RNG не приходит и не придёт: по seed воспроизводится будущее, по
остатку колоды — только настоящее.

`feed` — до **500** последних событий стола, от старых к свежим: открыв
стол в середине раздачи, админ видит её начало. Ленты в БД нет, она живёт
в памяти сервера и умирает с процессом.

Входящие сообщения:

| ← | Сообщение | Payload |
|---|---|---|
| ← | `room_state` | приходит только в ответе на join, внутри поля `room` |
| ← | `room_delta` | `{"event": "hand_started", "payload": {...}}` — доменное событие ядра без фильтрации; у приватных событий есть `"private": true` и `"user_id"` адресата |
| ← | `intent` | `{"at", "user_id", "seat", "topic", "event", "payload", "seq"}` — сырой запрос игрока |
| ← | `intent_result` | `{"at", "user_id", "event", "outcome": "ok"\|"error", "code", "latency_us"}` |

`intent` и `intent_result` приходят **парой** на каждое сообщение игрока,
включая отклонённые: у отклонённого `outcome: "error"` и код отказа. Это
и делает режим отладочным, а не «красивым реплеем».

**Канал ничего не принимает, кроме `ping`.** Любое другое сообщение
получит `illegal_action`. Закрыть стол или поставить турнир на паузу
можно только по HTTP, где есть причина и запись в журнале.

Открытие и закрытие наблюдения пишутся в `admin_audit`.

### `admin:tournament:<id>`

Join отвечает карточкой турнира (тот же формат, что `GET /admin/games/mtt/:id`).

| ← | Сообщение | Payload |
|---|---|---|
| ← | `tournament_delta` | `{"event": "level_up", "payload": {...}}` |
| ← | `tournament_state` | карточка целиком после каждого события |

Тоже только чтение: входящее — `ping`.

## 10. Сборка и окружение

* Адрес бэкенда — из `.env` (`VITE_API_URL`), выбирается **на сборке**.
  Переключателя окружения в UI быть не должно: он рано или поздно приведёт
  к операции не в том руме.
* Окружение показывается крупной плашкой в шапке: `PROD` красным,
  `TEST` серым.
* CORS настраивается на сервере списком origin'ов
  (`config :block_poker, :admin_origins`). Origin панели нужно сообщить
  бэкендерам до первой сборки — иначе браузер не пустит ни один ответ.

## 11. Экраны

1. **Логин.**
2. **Пользователи** — таблица с пагинацией, поиском, сортировкой,
   балансами обеих валют; строка раскрывается в карточку.
3. **Карточка игрока** — балансы, выписка, текущие посадки, история банов,
   кнопки: бан/разбан, начислить, списать себе. Каждая — модалка с
   обязательной причиной и подтверждением суммы прописью.
4. **Игры** — четыре вкладки поверх одного эндпоинта, живое обновление
   по `admin:games`.
5. **Стол (god-mode)** — слева визуализация стола со всеми открытыми
   картами, справа лента `intent` / `intent_result` / `room_delta` с
   фильтром по игроку и типу, автоскролл с паузой, экспорт видимого куска
   ленты в JSON. Вкладка показывается **только** при
   `observer_enabled: true`.
6. **Журнал** — `admin_audit` с фильтрами.
