# Клиент. Задача 35. Баннеры

Документ для разработчика Electron-клиента. Новая возможность, ничего
существующего не ломает: пока в панели не завели ни одного баннера,
сервер на все места отвечает `404`, и клиент ведёт себя ровно как сейчас.

Баннер — это картинка со ссылкой и подписью, которую администратор
ставит в конкретное место интерфейса, не выпуская новую сборку клиента.

---

## 1. Что появилось на сервере

Одна публичная ручка:

```
GET /api/banners/:place
```

Токена не требует и не принимает — по той же причине, что и
`GET /api/client/version`: баннер `OnRunApplication` показывается на
запуске приложения, когда логина ещё не было.

Ответ `200`:

```json
{
  "place": "CashGameLobbyTop",
  "image": "https://cdn.example/banners/CashGameLobbyTop-3xKq7Zp1a9Bc.png",
  "helper": "Новые столы с рейкбеком",
  "link": "https://example.com/promo"
}
```

* `image` — **готовый абсолютный URL**. Собирать его из чего-либо не
  нужно; на окружении без отдельного CDN он приходит путём от корня
  (`/banners/...`), и тогда его надо разрешить относительно `API_URL`.
* `helper` и `link` — могут быть `null` по отдельности. Баннер без
  ссылки — просто картинка, кликать её не надо. Баннер без подписи —
  картинка без текста.
* `image` не бывает `null`: баннера без картинки на сервере не существует.

Ответ `404` в единой форме ошибок (`{"code": "not_found", ...}`) —
**штатный и частый**: место пустое либо такого места вообще нет. Реакция
одна: не рисовать блок. Ошибку показывать нельзя и логировать как
проблему не нужно.

---

## 2. Места показа

Список закрыт на сервере. Незнакомая строка получает `404`, новые места
заводятся правкой сервера и этого документа — то есть согласованно с
клиентом, а не втихую из панели.

| `place` | Где показывать |
|---|---|
| `CashGameLobbyTop` | шапка вкладки кэш-игр в лобби |
| `SitAndGoLobbyTop` | шапка вкладки Sit&Go |
| `TournamentsLobbyTop` | шапка вкладки турниров |
| `OfcLobbyTop` | шапка вкладки китайского покера |
| `PersonalBlock` | личный блок игрока (профиль/кошелёк) |
| `OnRunApplication` | экран запуска приложения, до логина |

---

## 3. Что делать в клиенте

### 3.1. Загрузка

Запрос — обычный `GET` из `main` рядом с `getJson` в `src/main/http.ts`
(та же публичная ветка, что и версия клиента), результат в renderer через
IPC, по образцу `history`. В renderer — хук вида `useBanner(place)`,
возвращающий `banner | null`.

Ключевые требования:

* **`404` — это `null`, а не ошибка.** Никаких алертов и никаких повторов.
* **Сеть недоступна — тоже `null`.** Баннер не может помешать открыть
  лобби: отсутствие рекламного блока игрок не заметит, а модалка «сервер
  недоступен» поверх экрана запуска сломает вход.
* Запрашивать один раз при монтировании места. Пуша по сокету нет и не
  планируется: баннер меняется раз в неделю, а не раз в раздачу.
* `OnRunApplication` запрашивается **до** логина — он не должен зависеть
  от наличия токена ни в одной ветке кода.

### 3.2. Отрисовка

* Ссылки открываются **во внешнем браузере**, а не внутри окна Electron:
  `shell.openExternal` через IPC, как это уже делается для внешних
  ссылок. Открывать произвольный URL в окне приложения нельзя.
* Открывать только `http:` и `https:` — схему проверить перед вызовом.
  URL приходит из панели, но панель это тоже ввод.
* `link: null` — блок некликабельный, без курсора-указателя.
* Пропорции картинки задаёт клиент (фиксированная высота + `cover`):
  сервер размер не навязывает и не проверяет.

### 3.3. CSP

Картинка грузится с внешнего хоста. Если в `img-src` политики renderer'а
он не разрешён, баннер молча не отрисуется — проверить это первым делом.

---

## 4. Кэш

`image` содержит случайный суффикс в имени файла и меняется при каждой
замене картинки, поэтому содержимое конкретного адреса неизменно, и
сервер отдаёт его с `max-age=86400`. Своего кэша заводить не надо:
Chromium сделает это сам, а новую картинку клиент увидит сразу — у неё
уже другой адрес.

Сам JSON-ответ ручки не кэшируется. Дёргать его чаще, чем при открытии
экрана, всё равно незачем.

---

## 5. Чек-лист

- [ ] `GET /api/banners/:place` в `main`, без токена, результат через IPC.
- [ ] `404` и сетевая ошибка дают `null`, а не всплывающую ошибку.
- [ ] Шесть мест из §2 подключены; пустое место не оставляет дыры в вёрстке.
- [ ] `OnRunApplication` показывается до логина и не ждёт токена.
- [ ] Клик открывает ссылку во внешнем браузере; схема проверена.
- [ ] `helper: null` и `link: null` обрабатываются по отдельности.
- [ ] `img-src` в CSP разрешает хост картинок.
