# Клиент. Задача 2. Лобби, столы, посадка

Документ для разработчика Electron-клиента. Продолжает
[задачу 1](1_UserSecurity.md): аккаунт и WebSocket уже есть, теперь появились
**лобби и столы**.

**Раздачи ещё нет.** Стол умеет ровно одно: принимать и отпускать игроков,
корректно двигая деньги. Карты, ставки, улицы и вскрытие — следующая задача.
Не имитируй их заглушками: протокол сообщений раздачи ещё не зафиксирован.

Читать вместе с §5 `CLAUDE.md` (транспорт и протокол).

---

## 1. Что появилось

Два канала. Оба — по уже открытому сокету, новых HTTP-ручек нет и не будет:
игровое взаимодействие через HTTP недоступно в принципе.

| Топик | Назначение |
|---|---|
| `lobby` | список лимитов, число игроков, быстрый вход |
| `table:<room_id>` | конкретная комната: места, посадка, уход, докупка |

Ключевое различие, которое стоит понять до кода:

* **Шаблон (`setting_id`)** — это *лимит*: «NL10 6-max», блайнды 5/10, шесть
  мест. Живёт вечно, лежит в БД, показывается в лобби.
* **Комната (`room_id`)** — это *живой стол*, развёрнутый из шаблона. Их под
  одним шаблоном может быть много, они появляются и исчезают по мере
  наполнения. Подписка на стол идёт по `room_id`.

Игрок в интерфейсе выбирает **лимит**, а не комнату. Комнату сервер подберёт
сам — см. `quick_seat` (§4).

---

## 2. Общие правила

Всё из §2 задачи 1 остаётся в силе. Дополнительно:

* **Все суммы — целые в минимальных единицах** (центы для `main`, фишки для
  `play_money`). Никаких дробных: `4.5` в поле суммы сервер отвергнет
  как `validation_failed`.
* **Клиент никогда не считает деньги сам.** Не вычитай бай-ин из баланса,
  не складывай стеки. Показывай ровно то, что прислал сервер.
* `user_id` в payload сервер **игнорирует** — личность берётся из токена
  соединения. Отправлять его бессмысленно.
* Ответ на любое сообщение — либо `{:ok, payload}`, либо
  `{:error, {"code": ..., "message": ...}}`. Ветвись по `code` (§6).

## 3. Канал `lobby`

### Подключение

```js
const lobby = socket.channel("lobby", {})
lobby.join()
  .receive("ok", ({ settings }) => renderLobby(settings))
  .receive("error", (err) => showError(err))
```

Ответ на `join` — сразу полная витрина, отдельный запрос не нужен.

### Структура витрины

```json
{
  "settings": [
    {
      "setting_id": "6f1c...",
      "name": "NL10 6-max",
      "game_type": "texas_holdem",
      "currency": "play_money",
      "small_blind": 5,
      "big_blind": 10,
      "ante": 0,
      "ante_type": "big_blind",
      "max_players": 6,
      "min_buy_in": 400,
      "max_buy_in": 1000,
      "players_total": 14,
      "visuals": { "felt_color": "#2A5FA8", "background_color": "#14203A" },
      "rooms": [
        { "room_id": "a1b2...", "seats_taken": 6, "max_players": 6, "draining": false },
        { "room_id": "c3d4...", "seats_taken": 2, "max_players": 6, "draining": false }
      ]
    }
  ]
}
```

Что важно:

* `min_buy_in` / `max_buy_in` приходят **уже в фишках**, пересчитанные из
  больших блайндов. Не умножай ничего сам. `max_buy_in: null` — стол без
  верхнего предела.
* `players_total` — сумма по всем комнатам лимита.
* `rooms` показывать по умолчанию не нужно: это раскрывающийся список для тех,
  кто хочет выбрать стол вручную. Обычный путь — кнопка «Сесть».
* `draining: true` — комната доигрывает и закрывается. Новых игроков не
  принимает; в списке её лучше не показывать вовсе.
* **Показываются все включённые лимиты, включая пустые** — игрок должен
  видеть, за что он в принципе может сесть. Лимитов много (в стандартной
  сетке 72), поэтому пустые уровни имеет смысл сворачивать в интерфейсе,
  а не показывать наравне с живыми.

### `visuals` — оформление стола

`felt_color` — цвет сукна, `background_color` — цвет фона комнаты. Обычные
hex-строки (`#RRGGBB`, допустим и `#RRGGBBAA`). Задаются оператором на каждый
лимит и приходят и в лобби, и в снапшоте стола.

Это **только цвета**, не текстуры и не темы. Рисуй стол своей геометрией,
подставляя эти два значения. Если поле почему-то не пришло — используй свой
дефолт, не падай.

### Обновления

Опроса нет. При любом изменении занятости, открытии или закрытии комнаты
в топик приходит push:

```
"lobby_delta"  { ... тот же объект, что и элемент settings ... }
```

Это **полное состояние одного лимита**, а не дельта полей: просто замени
элемент с этим `setting_id` целиком.

### Список по запросу

```
"list" %{}  →  {:ok, {"settings": [...]}}
```

Нужен после реконнекта или если состояние в UI разъехалось. В обычном потоке
не требуется.

## 4. Быстрый вход: `quick_seat`

Основной способ сесть за стол. Запрос адресуется **лимиту**:

```js
lobby.push("quick_seat", { setting_id, buy_in: 40000 })
  .receive("ok", ({ room_id, seat, stack }) => openTable(room_id))
  .receive("error", ({ code }) => showError(code))
```

Сервер сам находит комнату со свободными местами и сажает на первое свободное.
Если между выбором комнаты и посадкой её успели заполнить — он **сам перейдёт
к следующей**, а не вернёт ошибку. Клиенту ретраить не нужно.

Ответ:

```json
{ "room_id": "a1b2...", "seat": 3, "stack": 40000,
  "waiting_for_bb": true, "can_post": false }
```

Получив `room_id`, подключайся к каналу `table:<room_id>` (§5). Посадка уже
произошла — повторный `join_seat` не нужен и вернёт `already_seated`.

Ошибки: `invalid_buy_in`, `insufficient_funds`, `no_seats_available`,
`validation_failed`.

> `no_seats_available` означает, что у лимита исчерпан лимит комнат. Это
> нормальная ситуация под пиковой нагрузкой: предложи другой лимит, не ретрай.

## 5. Канал `table:<room_id>`

### Подключение

```js
const table = socket.channel(`table:${roomId}`, {})
table.join().receive("ok", (snapshot) => renderTable(snapshot))
```

Подключиться может **любой аутентифицированный игрок**, не только сидящий:
наблюдение за столом разрешено. Отказ в `join` приходит только если комнаты
нет (`not_found`) — например, она закрылась, пока игрок кликал.

### Снапшот стола

Ответ на `join` и на сообщение `table_state`:

```json
{
  "room_id": "a1b2...",
  "setting_id": "6f1c...",
  "name": "NL10 6-max",
  "small_blind": 5, "big_blind": 10, "ante": 0,
  "max_players": 6,
  "action_seq": 0,
  "phase": "idle",
  "button_seat": 3,
  "hands_played": 0,
  "visuals": { "felt_color": "#2A5FA8", "background_color": "#14203A" },
  "seats": [
    { "seat": 1, "status": "playing", "user_id": "...", "name": "Player_1",
      "avatar": "/users/avatars/default.png", "stack": 40000,
      "waiting_for_bb": false, "missed_blinds": 0 },
    { "seat": 2, "status": "empty", "user_id": null, "name": null,
      "avatar": null, "stack": 0,
      "waiting_for_bb": false, "missed_blinds": 0 }
  ],
  "you": { "seated": true, "seat": 1, "stack": 40000, "status": "playing",
           "waiting_for_bb": false, "post_required": false,
           "can_post": true, "missed_blinds": 0 }
}
```

* `seats` — всегда все места стола, включая пустые, отсортированы по номеру.
* `name` и `avatar` — снимок профиля на момент посадки: у пустого места они
  `null`. Загрузки аватаров пока нет, `avatar` всегда дефолтный путь.
* `you.seated: false` — игрок наблюдает, места у него нет. Тогда остальных
  полей `you` нет.
* `phase` — `idle` (простой), `button_draw` (идёт розыгрыш кнопки),
  `hand` (идёт раздача; появится в следующей задаче).
* `action_seq` — счётчик стола. Сейчас он только растёт и ни на что не влияет;
  **сохраняй его** — со следующей задачи его нужно будет присылать обратно
  вместе с игровым действием.

Снапшот **персональный**: сервер формирует его отдельно для каждого игрока
и вырезает то, что игрок видеть не должен. Сейчас скрывать нечего, но правило
уже действует — не строй логику на том, что снапшот одинаков у всех.

### Посадка на выбранное место

Путь для тех, кто открыл комнату из лобби и ткнул в конкретное кресло:

```
"join_seat" %{seat: 3, buy_in: 40000, entry: "wait_bb" | "post"}
```

Ответ — как у `quick_seat`. Ошибки: `seat_taken`, `already_seated`,
`invalid_seat`, `invalid_buy_in`, `insufficient_funds`, `room_closing`.

**Один игрок — одно место в комнате.** За разными комнатами (в том числе
одного лимита) сидеть можно: мультитейблинг разрешён.

### Вход в игру: `entry`

Сев за стол, игрок **не начинает играть немедленно**. Иначе вход становится
способом не платить блайнды: сел за кнопкой, сыграл лучшие позиции бесплатно,
встал перед блайндом.

Два варианта:

* `"wait_bb"` (по умолчанию) — ждать своего большого блайнда. Карты не
  сдаются, стек не трогается.
* `"post"` — войти сразу, внеся сумму большого блайнда.

**`entry` — это намерение, а не решение.** Сервер может решить иначе: на
хедз-апе ожидания нет, на большом блайнде и сразу за ним вступление
немедленное, а после недавнего ухода из этой же комнаты доступен только post.
Смотри на ответ и на снапшот, а не на то, что отправил.

Рисуй кнопку «Ждать BB / Войти сейчас» по полям `you`:

| Поле | Что значит |
|---|---|
| `waiting_for_bb: true` | ждёт блайнда, карт не получит |
| `post_required: true` | ждать нельзя, войти можно только за post |
| `can_post: true` | кнопка «Войти сейчас» доступна |
| `missed_blinds: n` | сколько обязательных ставок пропущено |

Если `can_post: false` и `waiting_for_bb: true` — вариантов нет, показывай
только «ожидание блайнда».

### Уход и докупка

```
"leave_seat" %{}            → {:ok, {"room_id": ..., "cashed_out": 41200}}
"add_chips"  %{amount: 500} → {:ok, {"room_id": ..., "seat": 3, "stack": 40500}}
"sit_out"    %{}            → :ok
"sit_in"     %{}            → :ok
```

* `leave_seat` возвращает в кошелёк **текущий стек**, а не сумму бай-ина.
  `cashed_out: 0` — законный ответ, если игрок проиграл всё.
* `add_chips` доступна **между раздачами в любой момент**, независимо от
  текущего стека; верхняя граница — `max_buy_in` лимита. Во время раздачи —
  `hand_in_progress`.
* `sit_out` — пропускать раздачи, оставаясь за столом. `sit_in` — вернуться;
  с нулевым стеком вернёт `zero_stack`, сначала нужна докупка.

### События стола

Приходят пушем всем подписчикам топика:

| Событие | Когда | Payload |
|---|---|---|
| `seat_taken` | кто-то сел | `{seat, status, user_id, name, avatar, room_id}` |
| `seat_left` | кто-то встал | `{room_id}` |
| `chips_added` | докупка | `{seat, stack, room_id}` |
| `seat_disconnected` | у игрока оборвалась связь | `{seat, room_id}` |
| `seat_reconnected` | игрок вернулся | `{seat, room_id}` |
| `seat_sitting_out` | grace истёк, игрок выключен из игры | `{seat, reason, room_id}` |
| `button_draw` | розыгрыш кнопки | см. ниже |
| `button_ready` | анимация окончена, кнопка назначена | `{button_seat, room_id}` |
| `rebuy_expired` | окно докупки истекло | `{seat, user_id, room_id}` |

События `seat_*` намеренно **не содержат полного состояния стола**: они
говорят, что изменилось. Если состояние в UI разошлось — запроси
`table_state`, это дешёвая операция.

### Розыгрыш кнопки

Когда за столом впервые собирается достаточно игроков, кнопка дилера не
назначается молча — она разыгрывается открытой сдачей по карте:

```json
"button_draw" {
  "cards": [
    { "seat": 1, "card": { "rank": 14, "suit": "S" } },
    { "seat": 4, "card": { "rank": 9,  "suit": "H" } }
  ],
  "button_seat": 1,
  "animation_ms": 3000,
  "room_id": "a1b2..."
}
```

* Порядок сдачи — это порядок элементов `cards`, отдельного индекса нет.
* Карты **открытые и одинаковые для всех**: смысл процедуры в том, чтобы
  игрок видел, что позиция досталась не по решению сервера. Не прячь их.
* `rank` — 2..14 (14 = туз), `suit` — `"S"` / `"H"` / `"D"` / `"C"`.
  Старшая карта берёт кнопку; при равных рангах решает масть `♠ > ♥ > ♦ > ♣`.
  Пересдачи не бывает.
* `animation_ms` — сколько времени у тебя на анимацию. Ровно столько сервер
  ждёт перед стартом первой раздачи и присылает `button_ready`.
* Игрок, подключившийся в середине анимации, получает обычный `table_state`
  с уже назначенной кнопкой. Догонять анимацию не нужно — результат от неё
  не зависит.

### Разрыв соединения

Разрыв — **не** уход из-за стола и не cash-out. Место держится, стек на месте:

1. Связь оборвалась → остальным уходит `seat_disconnected`.
2. Игрок вернулся внутри grace-окна → `seat_reconnected`, можно играть дальше.
   Клиенту достаточно заново подключиться к `table:<room_id>` — снапшот
   придёт в ответе на `join`.
3. Окно истекло → `seat_sitting_out`, игрок пропускает раздачи, но место и
   фишки остаются за ним.

Отсюда практическое требование: **не вызывай `leave_seat` при потере сети**.
Просто переподключайся.

### Нулевой стек

Проиграв весь стек, игрок **не встаёт немедленно**: он переводится в
`sitting_out` и получает время на докупку. Показывай предложение докупиться;
`add_chips` в пределах `[min_buy_in, max_buy_in]` возвращает его в игру
со следующей раздачи. Если время вышло — придёт `rebuy_expired`, и место
освобождается.

Автодокупку не делай: молча списывать деньги из кошелька нельзя.

## 6. Коды ошибок

К списку из задачи 1 добавились:

| `code` | HTTP | Когда | Что делать клиенту |
|---|---|---|---|
| `seat_taken` | 409 | место заняли раньше | обновить стол, предложить другое место |
| `already_seated` | 409 | игрок уже сидит в этой комнате | ничего; вероятно, двойной клик |
| `invalid_seat` | 422 | такого места за столом нет | баг клиента, логировать |
| `invalid_buy_in` | 422 | сумма вне `[min_buy_in, max_buy_in]` | подсветить поле суммы |
| `insufficient_funds` | 422 | не хватает денег в кошельке | предложить другой лимит |
| `no_seats_available` | 409 | у лимита нет свободных мест | предложить другой лимит, **не ретраить** |
| `not_seated` | 409 | действие требует места за столом | обновить состояние |
| `hand_in_progress` | 409 | во время раздачи так нельзя | повторить между раздачами |
| `room_closing` | 409 | комната закрывается | вернуться в лобби |
| `zero_stack` | 409 | `sit_in` с нулевым стеком | предложить докупку |
| `reservation_lost` | 409 | резерв места истёк | повторить посадку |

Коды — закрытый список (`BlockPoker.ErrorCode`). Незнакомый код считай
фатальным и логируй, но не падай.

## 7. Кошелёк

Отдельного канала кошелька пока нет — он появится вместе с пополнениями.
Баланс приезжает в ответе `/login`, `/register` и `/refresh` (задача 1).

Бай-ин и cash-out **меняют баланс на сервере**, но пуша об этом сейчас нет.
Практический вывод: после посадки, ухода или докупки показывай в интерфейсе
стека то, что пришло в ответе, а баланс кошелька перечитывай при следующем
входе в лобби. Не пересчитывай его сам — расхождение будет означать баг
сервера, и его надо видеть.

---

## 8. Чего на сервере ещё нет

* **раздача целиком**: карты, ставки, улицы, вскрытие, победители, таймеры хода;
* чат за столом;
* лист ожидания на заполненные лимиты;
* приватные столы (`visibility` в шаблоне есть, но реализован только `public`);
* пуш об изменении баланса кошелька;
* история раздач.

## 9. Чек-лист приёмки клиента

1. Лобби открывается и показывает лимиты, включая пустые; цвета стола берутся
   из `visuals`.
2. `quick_seat` сажает за стол и открывает комнату; повторное нажатие не сажает
   второй раз, а даёт `already_seated`.
3. Посадка с суммой ниже `min_buy_in` → поле подсвечено, запрос не ушёл;
   при отправке корректно обработан `invalid_buy_in`.
4. Посадка на `play_money`-стол при нулевом `main` работает, и наоборот:
   валюта берётся из лимита, а не выбирается клиентом.
5. Двое садятся на одно место — второй получает `seat_taken` и видит
   обновлённый стол, а не зависшую кнопку.
6. Когда садится последний игрок, в лобби у **всех** подписчиков появляется
   новая комната.
7. Розыгрыш кнопки проигрывается анимацией `animation_ms`, все карты видны,
   кнопка встаёт на `button_seat`.
8. Севший игрок по умолчанию помечен «ждёт большого блайнда»; кнопка «Войти
   сейчас» показывается только при `can_post: true`.
9. Обрыв сети → клиент переподключается и возвращается на своё место со своим
   стеком; `leave_seat` при этом не вызывается.
10. `leave_seat` возвращает `cashed_out`, равный стеку, а не сумме бай-ина;
    место в снапшоте становится `empty`.
11. Докупка во время раздачи (когда она появится) даёт `hand_in_progress`,
    и клиент это объясняет, а не молчит.
12. Незнакомый код ошибки не роняет приложение.
