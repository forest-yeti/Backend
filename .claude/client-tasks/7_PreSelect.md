# Клиент. Задача 7. Преселект действий

Документ для разработчика Electron-клиента. Дополняет
[задачу 3](3_Hand.md) — действия в раздаче.

Правило общее для **всех форматов**: кэш, турнир, sit-n-go. Преселект —
это про порядок хода, а не про формат игры.

Без него мультитейблинг физически невозможен: за восемью столами нельзя
успеть везде, а мусор на префлопе решается ещё до того, как соперники
доиграли.

---

## 1. Что это

Игрок нажимает кнопку **до своей очереди**, и стол ходит за него, как
только очередь дойдёт. Решение принимает сервер: клиент не «нажимает
кнопку сам, когда придёт ход» — при лаге это даёт двойные действия и
пропущенные ходы.

Варианты ровно четыре:

| `action` | Поведение, когда дошла очередь |
|---|---|
| `fold` | сбросить, что бы ни произошло |
| `check_fold` | чек, если бесплатно; иначе сброс |
| `check` | чек, если бесплатно; **иначе выбор снимается**, ходит игрок |
| `call_any` | заплатить сколько попросят; бесплатно — просто чек |

Разница между `check` и `check_fold` — не мелочь, а вся суть механики.
`check` защищает руку, которую перебили ставкой: игрок просил чек, а не
пас, и стол не имеет права сбросить за него. `check_fold` — как раз для
мусора, с которым разговаривать не о чем. В интерфейсе это должны быть
две разные кнопки с разными подписями.

---

## 2. Сообщение

```
"preselect" %{action: "check_fold"}   →  {:ok, %{}}
"preselect" %{action: "none"}         →  снять выбор
```

* `"none"`, `"clear"` и отсутствие поля — одно и то же: снятие выбора.
  Отдельного сообщения на отмену нет.
* Неизвестное значение → `validation_failed`.
* Не сидит за столом → `not_seated`.
* `action_seq` тут не нужен: это не действие, а намерение.

Выбор можно сделать в любой момент, в том числе когда очередь **уже**
дошла до игрока, — тогда он срабатывает немедленно, как обычная кнопка.

---

## 3. Когда выбор пропадает

Выбор действует **только на текущее решение**. Он снимается:

| Событие | Почему |
|---|---|
| выбор сработал | ход сделан, ждать больше нечего |
| пришла новая улица (`street_dealt`) | обстановка на флопе не та, в которой выбирали |
| раздача закончилась | то же |
| `check` встретил ставку | игрок просил чек, а не пас |
| игрок встал с места | сессия за столом закончилась |

Клиент обязан гасить подсветку кнопок на всех этих событиях. Выбор,
переживающий улицу, — это ловушка, а не удобство.

---

## 4. Личные события

Оба приходят **только владельцу места**, в общий топик не попадают:
чужой преселект — это информация о чужой руке до хода.

```
"preselect_applied"  { "seat": 3, "action": "fold" }
"preselect_cleared"  { "seat": 3, "reason": "action_changed" }
```

* `preselect_applied` — стол сходил за игрока. Обычное событие действия
  (`action_taken`) при этом тоже придёт, всем.
* `preselect_cleared` с `reason: "action_changed"` — выбранный `check`
  встретил ставку: кнопка гаснет, ход возвращается игроку, и сразу же
  приходит обычный `action_prompt`.

В снапшоте свой выбор лежит в `you.preselect` (`null`, если не выбран).
**В `seats[]` его нет** — и не должно появиться.

---

## 5. Что делает клиент

1. Показывает кнопки преселекта, когда идёт раздача, игрок в ней участвует
   и сейчас **не** его ход. В свой ход показываются обычные кнопки
   действия (нажатие на преселект в свой ход тоже сработает, но это
   вырожденный случай).
2. Подсвечивает выбранное. Повторное нажатие на ту же кнопку — снятие
   (`"none"`), это ожидаемое поведение.
3. Гасит подсветку по событиям из §3 — не дожидаясь ответа сервера на
   что-либо.
4. Не пытается применить выбор сам: свой `action` отправляет только
   в ответ на `action_prompt`, и только если игрок нажал кнопку вручную.

Про мультитейблинг: набор кнопок и подсветка — состояние **стола**, а не
приложения. При переключении между окнами столов выбор каждого сохраняется
на сервере, поэтому после реконнекта его достаточно прочитать из
`you.preselect`.

---

## 6. Чек-лист приёмки

* [ ] Четыре кнопки, `check` и `check_fold` — разные и подписаны по-разному.
* [ ] Повторное нажатие снимает выбор.
* [ ] Выбор гаснет на новой улице и в конце раздачи.
* [ ] `check` против ставки не сбрасывает руку: приходит
      `preselect_cleared`, кнопки хода становятся активными.
* [ ] Чужой преселект нигде не отображается и не приходит.
* [ ] После реконнекта состояние кнопок восстановлено из `you.preselect`.
* [ ] Клиент не отправляет `action` автоматически по своему таймеру.
