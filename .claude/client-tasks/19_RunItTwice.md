# Клиент. Задача 19. Run it twice

Документ для разработчика Electron-клиента.

Двое пошли ва-банк, борд не досдан. До того как сдать тёрн и ривер, сервер
спрашивает обоих: разыграть недостающие улицы **дважды**? Если согласились
оба — на столе появляется второй ряд карт борда, и каждый прогон забирает
половину банка. Отказался любой — всё идёт как обычно, одним бордом.

Что важно понять до начала работы: **второй прогон не удваивает раздачу.**
Карманные карты те же, банк тот же, рейк тот же. Удваивается только борд.
Игрок, выигравший оба прогона, забирает банк целиком; выигравший один —
ровно половину. Именно ради этого функция и существует: она уменьшает
дисперсию, не меняя матожидания.

Функция есть только в кэш-игре. В турнирах её не будет никогда — ветку
«а если турнир» писать не нужно.

---

## 1. Когда появляется окно согласия

Приходит броадкастом в топик `table:<id>`:

```
"run_it_twice_offer" %{seats: [3, 5], deadline_ms: 8000}
```

* `seats` — два места, которых спрашивают. Всегда ровно два.
* `deadline_ms` — сколько времени на ответ **с момента получения**.

Окно показывается игроку, **чьё место есть в `seats`**. Остальным за столом
и наблюдателям окно не показывается — но им полезно показать нейтральную
подсказку вида «игроки решают, разыграть ли дважды», иначе стол на
несколько секунд необъяснимо замирает.

**Условий появления на клиенте не вычисляем.** Ни «сколько нас осталось»,
ни «полон ли борд», ни «разрешено ли за этим столом» — сервер уже всё
проверил и прислал предложение только тогда, когда оно законно. Если
события нет — вопроса нет.

Порядок событий фиксирован и на него можно опираться: **карты вскрываются
раньше вопроса.** Сначала приходит `all_in_showdown` с руками и эквити,
и только потом `run_it_twice_offer`. Игрок принимает решение, видя расклад
и проценты, — так же, как в любом руме. Не показывайте окно поверх ещё не
отрисованных карт.

---

## 2. Ответ

```
"run_it_twice"  %{accept: true}
```

Топик `table:<id>`. Отправляется один раз. Повторная отправка вернёт
`already_answered` — это не ошибка пользователя, а гонка (двойной клик,
лаг), и показывать её игроку не нужно: просто игнорируйте.

**Молчание — отказ.** Истёк `deadline_ms` — сервер закрывает окно сам,
и раздача идёт одним бордом. Клиент по таймауту ничего не отправляет:
он просто гасит окно. Отправлять «за игрока» автоматический отказ не надо —
сервер сделает это сам и, что важнее, сделает это по своим часам.

Разрыв соединения во время окна — тоже отказ. Grace-период реконнекта,
который спасает место при разрыве в свой ход, здесь не работает: фишки
уже в банке, ждать некого.

Коды ошибок, которые может вернуть сервер: `run_it_twice_not_offered`
(окно уже закрылось), `not_a_contender` (место не из `seats`),
`already_answered`. Все три означают, что клиент разошёлся с сервером;
правильная реакция — закрыть окно, а не ретраить.

---

## 3. Решение

```
"run_it_twice_decided" %{accepted: true, answers: %{"3" => true, "5" => false}}
```

Броадкаст всем. `accepted` — итог (`true` только если согласились оба),
`answers` — кто как ответил; неответивший в `answers` отсутствует.

Приходит **сразу**, как только исход определён: при отказе первого же
игрока сервер не ждёт второго ответа. То есть окно у второго игрока может
погаснуть раньше, чем истёк его `deadline_ms`, — это нормальный сценарий,
а не сбой.

Показывать `answers` поимённо на столе — на ваше усмотрение; минимум,
который нужен, — короткое сообщение «играем дважды» / «играем один раз»,
чтобы отказ не выглядел зависанием.

## 4. Два борда

При согласии в раздачу борда добавляется второй ряд:

```
"street_dealt" %{street: "turn", board: [...], board_2: [...] | null, pot: ...}
```

* `board_2: null` — обычная раздача. Так приходит **всегда**, кроме принятого
  run it twice. Ветвление делается по `board_2`, а не по флагу режима.
* Оба борда приходят в **одном событии, одной улицей**: прогоны идут
  синхронно, тёрн первого и тёрн второго сдаются одновременно. Не пытайтесь
  доиграть первый борд до ривера, а потом второй — сервер шлёт их парами.

Первые карты обоих бордов совпадают: улицы, легшие до олл-ина, принадлежат
обоим прогонам. Расходятся борды с той улицы, на которой торговля кончилась.
Визуально это удобно рисовать как общий префикс и две расходящиеся хвостовые
карты, но полный список карт каждого борда всё равно приходит целиком —
диффать не нужно.

## 5. Эквити и ауты: у каждого прогона свои

```
"equity_update" %{runs: [
  %{run: 1, equity: [%{seat: 3, win: ..., tie: ..., equity: ..., outs: [...]}, ...]},
  %{run: 2, equity: [...]}
]}
```

Тот же список приходит и внутри `all_in_showdown` — в поле `equity`: в
момент вскрытия прогон ещё один, поэтому там всегда `[%{run: 1, …}]`.

Обычная раздача — `runs` длины 1. Принятый run it twice — длины 2, и
проценты в них **разные**, потому что борды разные. Показывать один общий
процент нельзя — он не соответствует ничему.

Тонкость, которую нужно просто принять и не «чинить» на клиенте: **ауты
второго прогона могут отличаться от аутов первого при одинаковом борде.**
Колода у прогонов общая, и карта, уже легшая на первый борд, во втором
выйти не может.

> У игрока на флопе четыре аута. На тёрне первого прогона приходит один из
> них — игрок переехал, но на ривере всё равно проиграл. На втором прогоне
> сервер покажет **три** аута, а не четыре: четвёртая карта лежит на первом
> борде.

Это не рассинхрон и не баг отображения. Сервер считает ауты каждого прогона
с учётом карт чужого борда. Клиент рисует пришедшие числа и ничего не
пересчитывает — счёт аутов на клиенте запрещён так же, как счёт банка.

## 6. Итог раздачи

`hand_finished` становится списочным по прогонам — **всегда**, включая
обычную раздачу:

```
"hand_finished" %{
  runs: [
    %{run: 1, board: [...], pots: [%{amount: ..., winners: [...]}]},
    %{run: 2, board: [...], pots: [...]}
  ],
  payouts: %{"3" => 12500, "5" => 12500},
  rake: 300,
  showdown: true,
  shown: [...]
}
```

Что здесь важно:

* `runs` длины 1 — обычная раздача. Отдельного «старого» формата больше нет,
  и парсер должен читать список в обоих случаях.
* `payouts` — **плоский итог по раздаче**, сумма по обоим прогонам. Именно
  его надо анимировать как приезд фишек в стек. Складывать выигрыши прогонов
  самостоятельно не нужно и не следует.
* `rake` — **один на раздачу**, а не по прогону. Не умножайте на два.
* Банк делится пополам; при нечётном банке лишняя фишка уходит победителю
  **первого** прогона. Если решите показывать размер выигрыша по каждому
  прогону, берите его из `pots` соответствующего `run`, а не делите банк
  сами — с остатком вы разойдётесь с сервером на одну фишку.

Хорошая подача итога: подсветить победителя над каждым бордом отдельно
(«первый прогон», «второй прогон»), а суммарный приезд фишек показать один
раз по `payouts`.

---

## 7. Реконнект

Игрок может отвалиться и вернуться в любой момент, в том числе внутри окна
согласия. Снапшот `table_state` содержит всё, что нужно, чтобы восстановить
экран:

* `showdown` — блок доводки с открытыми картами и эквити (уже есть сегодня);
* `run_it_twice: %{seats: [3, 5], deadline_ms: 5200}` — открытый вопрос
  с **остатком** времени; `null`, если вопроса нет или он уже решён.
  Вернувшийся внутри окна игрок может ответить;
* `hand.board_2` — второй борд, если прогонов два, иначе `null`.

Отдельного запроса «а что там сейчас» нет и не нужно: `table_state`
самодостаточен. Восстанавливая окно, берите дедлайн из снапшота, а не из
запомненного до разрыва.

---

## 8. Чего делать не нужно

* Не вычислять на клиенте, можно ли предложить run it twice.
* Не отправлять автоматический отказ по таймауту.
* Не пересчитывать ауты, эквити, доли банка и рейк.
* Не удваивать рейк и не удваивать банк в анимации.
* Не писать ветку «а если прогонов три» — их ровно два.
* Не писать ветку «а если турнир» — там функции нет.
