# Клиент. Задача 4. Фильтры и сортировка лобби

Документ для разработчика Electron-клиента. Дополняет
[задачу 2](2_CashGame.md), §3 «Канал `lobby`»: сам канал, витрина, `quick_seat`
и `lobby_delta` остаются прежними — у них появились **параметры**.

Ничего нового по HTTP не добавилось. Новых топиков тоже нет.

---

## 1. Главное правило

**Порядок и отбор считает сервер.** Клиент не сортирует список сам, не решает,
что такое «микролимит», и не прячет строки локально. Он отправляет выбранные
галки, получает готовый список и рисует его сверху вниз в том порядке, в
котором элементы пришли в массиве `settings`.

Причина простая: категории завязаны на блайнды и валюту, то есть на правила
рума. Захардкоженный на клиенте список лимитов разъедется с сервером в первый
же день, когда оператор добавит новый уровень.

---

## 2. Порядок по умолчанию

Когда не выбран ни один фильтр и не задана сортировка:

1. сперва все лимиты валюты **`main`** — от младшего к старшему (NL2, NL5,
   NL10, … до максимального);
2. затем тем же порядком все лимиты **`play_money`**.

Группировка по валюте сохраняется **всегда**, в том числе при явной сортировке:
`main` идёт выше, `play_money` — ниже. Сортировка работает внутри своей валюты.
Смешивать центы с игровыми фишками в одном упорядоченном списке бессмысленно.

Внутри одного лимита порядок стабильный (блайнды → число мест → анте), поэтому
строки не прыгают между обновлениями.

## 3. Новые поля витрины

К каждому элементу `settings` (и в `lobby_delta`, это тот же объект) добавились:

```json
{
  "setting_id": "6f1c...",
  "table_size": "six_max",
  "limit_tier": "micro",
  "seats_taken": 4,
  "max_players": 6,
  "players_total": 14
}
```

* `table_size` — формат стола: `heads_up` | `six_max` | `nine_max`.
* `limit_tier` — категория лимита: `micro` | `medium` | `high_roller`.
* `seats_taken` — занятость **той комнаты, куда посадит `quick_seat`**. Это то
  число, которое показывается в строке как «4/6»: `seats_taken` / `max_players`.
  Не путать с `players_total` — суммой по всем комнатам лимита.

Всё остальное (`rooms`, `visuals`, `min_buy_in`, …) — без изменений.

### Список допустимых значений

Ответ на `join` и на `list` теперь содержит второй ключ — `filters`:

```json
{
  "settings": [ ... ],
  "filters": {
    "game_types": ["texas_holdem"],
    "currencies": ["main", "play_money"],
    "table_sizes": ["heads_up", "six_max", "nine_max"],
    "limit_tiers": ["micro", "medium", "high_roller"],
    "sort_fields": ["limit", "occupancy"]
  }
}
```

**Панель фильтров строится по этому объекту, а не по списку в коде клиента.**
Когда на сервере появится вторая категория игры (Omaha), она приедет сюда сама,
и клиент не придётся перевыпускать. Подписи и иконки — на стороне клиента;
значения (`micro`, `six_max`) — ключи, их не переводим на бэкенде.

## 4. Запрос с фильтрами

Те же два сообщения, что и раньше, — просто с payload:

```js
const query = {
  game_types: ["texas_holdem"],
  currencies: ["main"],
  table_sizes: ["six_max", "nine_max"],
  limit_tiers: ["micro"],
  sort: { field: "limit", direction: "asc" }
}

// при подключении
const lobby = socket.channel("lobby", query)

// при смене галок в панели — без переподключения
lobby.push("list", query).receive("ok", ({ settings, filters }) => render(settings))
```

Правила:

* Все четыре списка **необязательны**. Отсутствующий или пустой список
  означает «фильтр не выбран» — то есть показать всё, а не ничего. Снятая
  последняя галка = пустой массив = полная витрина.
* Внутри одного фильтра значения складываются по **«или»**
  (`micro` + `high_roller` → микро и хайроллеры).
* Разные фильтры складываются по **«и»** (`main` + `heads_up` → хедз-апы на
  реальные деньги).
* `sort` необязателен; без него действует порядок по умолчанию (§2).
  `direction` по умолчанию `asc`.
* Неизвестное значение — **ошибка** `validation_failed`, а не молчаливое
  игнорирование: опечатка в фильтре не должна выглядеть как пустой рум.

### Сортировка

| `field` | `asc` | `desc` |
|---|---|---|
| `limit` | от младшего лимита к старшему | от старшего к младшему |
| `occupancy` | сперва пустые (0/9), в конце заполненные (9/9) | наоборот |

`occupancy` считается по `seats_taken` — по комнате быстрого входа, той самой,
чьё «4/6» видно в строке.

---

## 5. Категории лимитов

Границы задаёт сервер, клиенту их знать не нужно — он показывает то, что
пришло в `limit_tier`. Для понимания, что увидит игрок:

| Категория | `main` | `play_money` |
|---|---|---|
| `micro` | NL2 – NL10 | NL1000 – NL10000 |
| `medium` | NL20 – NL500 | NL30000 – NL50000 |
| `high_roller` | NL800 и выше | NL100000 и выше |

`table_size` выводится из числа мест: 2 → `heads_up`, 3–6 → `six_max`,
7–9 → `nine_max`.

---

## 6. Обновления при активном фильтре

`lobby_delta` приходит **только по лимитам, которые проходят текущий фильтр**.
Отфильтрованный лимит до клиента не доезжает вовсе — проверять его повторно
не нужно.

Фильтр запоминается на соединении и обновляется каждым `list`. Поэтому:

* сменил галки → отправь `list` с новым payload → дальше пуши идут уже по
  новому фильтру;
* переподключился → отправь `list` с текущим payload (или укажи его в `join`),
  иначе сервер вернётся к порядку по умолчанию.

Как и раньше, `lobby_delta` — это **полное состояние одного лимита**: замени
элемент с этим `setting_id` целиком. Позицию в списке при этом сервер не
пересчитывает — если сортировка по занятости и строка должна была переехать,
это делает клиент по тому же правилу (§4) или перезапрашивает `list`.

---

## 7. Чек-лист приёмки

* [ ] Без единой галки список идёт: `main` от NL2 вверх, затем `play_money`.
* [ ] Панель фильтров построена по `filters` из ответа сервера, а не по
      списку в коде.
* [ ] Снятие последней галки в группе возвращает полную витрину, а не пустую.
* [ ] Строка показывает `seats_taken`/`max_players`, а не `players_total`.
* [ ] Сортировка по занятости `asc` ставит пустые столы наверх, `desc` —
      заполненные.
* [ ] Смена фильтра идёт через `list` по открытому каналу, без переподключения
      сокета.
* [ ] Ответ `validation_failed` на фильтр показывается как ошибка клиента
      (баг), а не как «нет столов».
