# Клиент. Задача 8. Чат за столом

Документ для разработчика Electron-клиента. Дополняет
[задачу 2](2_CashGame.md) — канал `table:<room_id>`.

Чат общий для **всех форматов**: кэш, турнир, sit-n-go. Он про людей за
столом, а не про формат игры, поэтому никаких «если турнир» в клиенте.

Новых каналов нет: чат живёт в топике стола, на который клиент и так
подписан.

---

## 1. Правила

* **Писать может только сидящий за столом.** Наблюдатель чат читает, но
  не пишет: стол не знает его по имени и не отвечает за него. Попытка →
  `not_seated`.
* Длина — до **200 символов** (именно символов, не байтов: кириллица
  считается наравне с латиницей).
* Переводы строк и лишние пробелы схлопываются в один пробел. Сообщение
  в чате стола — одна строка. Это не косметика: «лесенка» из переводов
  строк — самый дешёвый способ вытолкнуть с экрана всё остальное.
* Частота — не больше **5 сообщений за 10 секунд** на игрока. Превышение →
  `chat_rate_limited`, сообщение не отправляется.
* Комната помнит **последние 20 сообщений**. Они приходят в снапшоте,
  чтобы вернувшийся после разрыва увидел, о чём говорили. Дальше история
  нигде не хранится и после закрытия стола не восстанавливается.

---

## 2. Сообщение и событие

Клиент → сервер:

```
"chat" %{text: "всем удачи"}   →  {:ok, <то же сообщение, что придёт в топик>}
```

Сервер → всем в топике стола:

```
"chat_message"
{
  "seat": 3,
  "user_id": "9f2c...",
  "name": "Hero",
  "text": "всем удачи",
  "at": "2026-08-18T12:34:56.123456Z"
}
```

* `text` приходит **уже очищенным** — рисуй как есть, не обрезай и не
  «доочищай» повторно.
* `name` — ник игрока на момент посадки; может быть `null`, если профиль
  без ника. Тогда показывай место (`Место 3`), а не пустоту.
* `at` — UTC. Локальное время — забота клиента.
* Своё сообщение приходит тем же событием, что и чужие. **Не рисуй его
  локально при отправке** — иначе на медленной сети оно задвоится.

В снапшоте стола: ключ `chat` — массив тех же объектов, старые первыми.

---

## 3. Коды ошибок

| Код | Когда | Что показать |
|---|---|---|
| `not_seated` | пишет наблюдатель | поле ввода вообще не показывать сидящим не за столом |
| `validation_failed` | пустое сообщение или не строка | ничего, просто не отправлять |
| `chat_too_long` | больше 200 символов | счётчик символов и блокировка отправки |
| `chat_rate_limited` | флуд | короткое «слишком часто», поле не очищать |

Первые три ловятся на клиенте до отправки — счётчиком символов и
неактивной кнопкой. Это не отменяет обработку ответа: сервер всё равно
проверяет сам, и его ответ — последнее слово.

---

## 4. Что делает клиент

1. Показывает поле ввода только сидящему за столом; наблюдателю — ленту
   без ввода.
2. Отправляет `"chat"` с сырым текстом. Обрезать пробелы и переводы строк
   на клиенте можно, но необязательно — сервер сделает это сам.
3. Дорисовывает сообщение **только** по `chat_message`.
4. При join/реконнекте заполняет ленту из `chat` в снапшоте.
5. Enter — отправка, Shift+Enter не нужен: сообщение однострочное.

---

## 5. Чек-лист приёмки

* [ ] Своё сообщение появляется один раз, а не два.
* [ ] Наблюдатель видит ленту, но не поле ввода.
* [ ] Счётчик символов считает символы, а не байты (200 «я» проходят).
* [ ] Многострочная вставка превращается в одну строку.
* [ ] Шестое сообщение за 10 секунд даёт понятную ошибку, а текст в поле
      не пропадает.
* [ ] После реконнекта в ленте видно последние сообщения из снапшота.
* [ ] Время сообщения показано в локальной зоне пользователя.
