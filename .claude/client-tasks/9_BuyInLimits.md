# Клиент. Задача 9. Границы докупки: правило изменилось

Документ для разработчика Electron-клиента. Правка к
[задаче 2](2_CashGame.md), §«Уход и докупка».

Маленькая задача, но **сломает существующий UI докупки**, если ничего не
менять: сервер начнёт отвечать `invalid_buy_in` на сумму, которую клиент
сейчас считает допустимой.

---

## 1. Что было не так

Сервер проверял нижнюю границу только при **нулевом** стеке. Игрок,
оставшийся после проигранной раздачи с парой фишек, формально нулём не
был — и мог докупить один большой блайнд, сев играть на 1.5bb за столом
с минимальным бай-ином в 40bb. Повторять это можно было бесконечно.

```
стек 0 фишек, докупка 1bb   → invalid_buy_in   (правильно)
стек 5 фишек, докупка 1bb   → ok               (баг)
```

---

## 2. Как стало

Проверяется **итоговый стек**, а не сумма докупки:

```
min_buy_in ≤ stack + amount ≤ max_buy_in
```

Отсюда три следствия, каждое из которых видно в интерфейсе:

1. **Докупка обязана довести стек до минимума стола.** 5 фишек + 395 —
   можно, 5 фишек + 10 — нельзя.
2. **Игроку со стеком выше минимума ничего не изменилось.** Он докупает
   любую сумму, лишь бы не перевалить за `max_buy_in`.
3. **Играть коротким стеком по-прежнему можно.** Правило про докупку, а не
   про право сидеть за столом: остаток от проигранной раздачи — законный
   стек, доигрывать им никто не мешает.

---

## 3. Что менять в клиенте

Границы поля докупки считаются от текущего стека, а не от лимита:

```js
const min = Math.max(minBuyIn - stack, 1)   // стек уже выше минимума → любая сумма
const max = maxBuyIn === null ? Infinity : maxBuyIn - stack
```

* `minBuyIn` / `maxBuyIn` — `min_buy_in` и `max_buy_in` из снапшота стола
  и из лобби, **уже в фишках** (сервер пересчитал их из больших блайндов).
* `max_buy_in: null` — стол без потолка, верхней границы нет.
* Если `stack >= minBuyIn`, нижняя граница — просто «больше нуля».
* Слайдер/поле, начинающийся с `minBuyIn` как раньше, на коротком стеке
  предложит слишком большую сумму, а на длинном — запретит законную
  докупку. Обе ошибки заметны сразу.

Ответ `invalid_buy_in` по-прежнему возможен (гонка с чужой докупкой,
устаревший снапшот) — обрабатывайте его как раньше, не считая багом.

---

## 4. Где это видно игроку

* **Диалог докупки** между раздачами.
* **Предложение докупиться при нулевом стеке** (§«Нулевой стек» задачи 2):
  там стек равен нулю, поэтому минимум — полный `min_buy_in`, как и было.
* **Короткий стек после проигранной раздачи** — новый случай: минимум
  в поле должен быть «сколько не хватает до минимума стола», и это стоит
  подписать словами, иначе цифра выглядит произвольной.

---

## 5. Чек-лист приёмки

* [ ] Со стеком 5 фишек поле докупки не даёт отправить 1bb.
* [ ] Со стеком 5 фишек сумма «до минимума стола» проходит.
* [ ] Со стеком выше минимума докупка на любую сумму до потолка работает.
* [ ] На столе без потолка (`max_buy_in: null`) верхняя граница не
      обрезается и ничего не падает.
* [ ] При нулевом стеке предложение докупиться показывает полный
      `min_buy_in`, как и раньше.
* [ ] `invalid_buy_in` от сервера показывается как ошибка ввода, а не как
      сбой приложения.
